PART 1. 이론 (3H)

1교시 · 사용자·그룹·권한 (50분)

1.1 왜 권한을 배워야 하는가

이 과정에서 권한 문제가 터지는 지점은 정해져 있습니다.

상황 증상 교과
pip install 시 권한 오류 Permission denied 교과 1·5
셸 스크립트 실행 안 됨 bash: ./run.sh: Permission denied 교과 4·14
Raspberry Pi에서 카메라 접근 실패 /dev/video0 권한 없음 교과 13
Jetson에서 GPIO 제어 실패 gpio 그룹 미포함 교과 13·14
팀 공유 데이터셋을 팀원이 못 읽음 Permission denied 교과 14·15

1.2 rwx 3×3 구조

-rwxr-xr--   1  kdt  ai-team  4096  Aug 26  run.sh
 └┬┘└┬┘└┬┘
  │  │  └── others(기타 사용자): r-- = 읽기만
  │  └───── group(그룹): r-x = 읽기+실행
  └──────── user(소유자): rwx = 읽기+쓰기+실행
기호 파일에서 디렉토리에서 ★
r (4) 내용 읽기 목록 조회(ls)
w (2) 내용 수정 파일 생성/삭제
x (1) 실행 진입(cd) 및 내부 접근

함정: 디렉토리에 r만 있고 x가 없으면 ls는 되는데 안으로 못 들어갑니다. 반대로 x만 있으면 목록은 못 보지만 정확한 파일명을 알면 접근됩니다.

1.3 8진수 표기

rwx = 4+2+1 = 7
rw- = 4+2   = 6
r-x = 4+0+1 = 5
r-- = 4     = 4
--- = 0
자주 쓰는 값 의미 용도
755 rwxr-xr-x 실행 스크립트, 디렉토리
644 rw-r--r-- 일반 파일, 설정 파일
700 rwx------ 개인 전용 폴더
600 rw------- SSH 개인키, API 키 파일 (필수)
444 r--r--r-- 데이터셋 원본 보호
775 rwxrwxr-x 팀 공유 디렉토리

1.4 명령어

chmod 755 run.sh          # 8진수 방식
chmod u+x run.sh          # 기호 방식: 소유자에게 실행 추가
chmod go-w data/          # group, others 에서 쓰기 제거
chmod -R 444 raw/         # 재귀 적용

chown kdt:ai-team file    # 소유자:그룹 변경 (sudo 필요)
chgrp ai-team file        # 그룹만 변경

umask                     # 기본 권한 마스크 (보통 0022)

1.5 sudo

sudo apt install tree     # 관리자 권한으로 실행
sudo -l                   # 내가 sudo로 뭘 할 수 있나

⚠️ sudo pip install 금지. 시스템 파이썬을 오염시켜 이후 conda 환경과 충돌합니다. 5일차에서 정확한 이유를 다룹니다. 패키지는 반드시 가상환경 안에서 설치합니다.

2교시 · 링크와 저장소 (50분)

2.1 하드링크 vs 심볼릭 링크

ln  원본 하드링크명        # 하드링크: 같은 inode를 가리킴
ln -s 원본 심볼릭링크명    # 심볼릭링크: 경로를 가리키는 바로가기 ★
하드링크 심볼릭링크
원본 삭제 시 데이터 유지 깨짐(broken link)
디렉토리 대상 불가 가능
파일시스템 넘기 불가 가능
실무 사용 빈도 낮음 높음

2.2 심볼릭 링크가 필요한 실제 상황 ★

문제: 조각김치 데이터 1,000장(원본 4848×2704, 수십 GB)을 train/val/test로 7:1.5:1.5 분할해야 합니다. 복사하면 용량이 2배가 됩니다. 학생 PC의 SSD는 512GB입니다.

해결: 원본은 한 곳에 두고, 분할 폴더에는 링크만 만듭니다.

cd ~/kdt-linux/dataset/kimchi
ln -s ../../raw/kimchi_0001.jpg images/train/kimchi_0001.jpg
ls -l images/train/            # l 로 시작, -> 로 원본 표시

교과 8·14의 데이터셋 분할 실습에서 이 기법을 그대로 씁니다. 5일차 split_dataset.sh에서 옵션으로 구현합니다.

2.3 디스크 용량 관리

df -h                     # 파일시스템별 여유 공간
du -sh ~/kdt-linux        # 특정 폴더 총 용량
du -sh */ | sort -rh      # 하위 폴더별 용량 큰 순 ★
du -h --max-depth=1 ~ | sort -rh | head

교과 5·8에서 체크포인트(.pt) 파일이 쌓여 디스크가 꽉 차는 사고가 자주 납니다. du -sh */ | sort -rh 는 그때 첫 번째로 치는 명령입니다.

3교시 · 표준 스트림과 파이프 (50분)

3.1 모든 명령어는 3개의 통로를 가진다

        ┌───────────────────┐
stdin ──▶│                    │──▶ stdout (표준 출력, 1)
  (0)    │      명령어         │
        │                    │──▶ stderr (표준 에러, 2)
        └───────────────────┘

3.2 리다이렉션

명령 > 파일          # stdout을 파일로 (덮어쓰기)
명령 >> 파일         # stdout을 파일에 추가
명령 2> 파일         # stderr만 파일로
명령 &> 파일         # stdout + stderr 둘 다
명령 2>/dev/null     # 에러 메시지 버리기 ★
명령 < 파일          # 파일을 stdin으로

실무 예시

python train.py > train.log 2>&1 &      # 학습 로그 전체를 파일로, 백그라운드 실행
find / -name "*.pt" 2>/dev/null         # 권한 오류 메시지 숨기고 결과만

2>&1 은 "stderr(2)를 stdout(1)이 가는 곳으로 합치라"는 뜻입니다. 교과 5·8·14의 장시간 학습에서 로그를 남길 때 반드시 씁니다.

3.3 파이프 — 리눅스의 핵심 철학

"하나의 프로그램은 한 가지 일만 잘 하게 만들고, 프로그램들이 함께 동작하도록 만들어라." — Unix 철학

명령A | 명령B        # A의 출력을 B의 입력으로

ls *.txt | wc -l                      # 텍스트 파일 개수
cat *.txt | cut -d' ' -f1 | sort | uniq -c | sort -rn
#  전체 라벨 → 첫 필드(클래스) 추출 → 정렬 → 개수 세기 → 많은 순

3.4 파이프 조립용 부품 명령어

명령 역할 자주 쓰는 옵션
cat 파일 내용 출력 -n 줄번호
head / tail 앞/뒤 N줄 -n 20, tail -f 실시간
wc 개수 세기 -l 줄, -w 단어, -c 바이트
sort 정렬 -n 숫자, -r 역순, -k2 2번째 필드
uniq 중복 처리 -c 개수, -d 중복만
cut 열 추출 -d' ' 구분자, -f1 필드
tr 문자 치환 tr ' ' '\n'
xargs 입력을 인자로 변환 -n1, -I{}
tee 화면 + 파일 동시 출력 -a 추가

3.5 아카이브와 압축

# 묶기 (create)
tar -cvf data.tar dataset/
tar -czvf data.tar.gz dataset/        # gzip 압축 ★
tar -cJvf data.tar.xz dataset/        # xz (더 작지만 느림)

# 풀기 (extract)
tar -xzvf data.tar.gz
tar -xzvf data.tar.gz -C /목적지/

# 내용만 보기 (list)
tar -tzvf data.tar.gz | head
옵션 의미
c create (묶기)
x extract (풀기)
t list (목록)
z gzip
v verbose
f file (파일명 지정, 항상 마지막)

암기법: "cvf 만들고, xvf 풀고, tvf 본다. 압축은 z 하나 더."

Step 2. 실행 권한의 의미 체험

cd ~/kdt-linux
cat > hello.sh << 'EOF'
#!/bin/bash
echo "안녕하세요, $(whoami) 님"
EOF

ls -l hello.sh            # -rwxrwxr-x
./hello.sh                # → 정상 실행

Step 3. 8진수로 정확히 지정

chmod 700 hello.sh; ls -l hello.sh      # rwx------
chmod 644 hello.sh; ls -l hello.sh      # rw-r--r--
./hello.sh                              # → 다시 Permission denied
chmod 755 hello.sh; ls -l hello.sh      # rwxr-xr-x
./hello.sh                              # → 실행됨

Step 4. 디렉토리의 x 권한 체험 ★

mkdir -p /tmp/perm_test/inner
echo "secret" > /tmp/perm_test/inner/data.txt

chmod 600 /tmp/perm_test/inner          # rw- : x 없음
ls /tmp/perm_test/inner                 # 목록은 보임(r)
cd /tmp/perm_test/inner                 # → Permission denied (x 없음)
cat /tmp/perm_test/inner/data.txt       # → Permission denied

chmod 700 /tmp/perm_test/inner
cd /tmp/perm_test/inner && cat data.txt # → 정상
cd ~

결론 정리하기 (노트에 기록): 디렉토리에서 r은 __, x는 ____ 이다.

Step 5. 실무 미션 — 데이터셋 권한 설계

요구사항

대상 권한 이유

raw/ 내부 파일 444 (r--r--r--) 읽기 전용
images/, labels/ 755 작업 공간
스크립트 .sh 755 실행 가능
meta/ 문서 644 일반 파일 
cd ~/kdt-linux/dataset/kimchi

# 원본 잠금

# 검증

chmod 444 raw/* && chmod 555 raw

실습 2-2 · 심볼릭 링크로 데이터셋 분할 (50분) ★

Step 1. 링크 기본 동작 확인

cd /tmp && rm -rf linktest && mkdir linktest && cd linktest
echo "원본 데이터" > original.txt

ln original.txt hard.txt          # 하드링크
ln -s original.txt soft.txt       # 심볼릭링크

ls -li                            # -i : inode 번호 표시
# original.txt 와 hard.txt 는 inode가 같음
# soft.txt 는 다른 inode, 크기가 작음, l 로 시작

cat hard.txt; cat soft.txt

rm original.txt                   # 원본 삭제
cat hard.txt                      # → 정상 (데이터 유지)
cat soft.txt                      # → No such file (깨진 링크)
ls -l soft.txt                    # 빨간색으로 표시됨

Step 2. 실무 적용 — 링크 방식 분할

cd ~/kdt-linux/dataset/kimchi

# 이미지 목록을 무작위로 섞어 700 / 150 / 150 으로 분할
ls raw/*.jpg | shuf --random-source=<(yes) > /tmp/all_imgs.txt
wc -l /tmp/all_imgs.txt

head -700 /tmp/all_imgs.txt              > /tmp/train.txt
sed -n '701,850p' /tmp/all_imgs.txt      > /tmp/val.txt
sed -n '851,$p'   /tmp/all_imgs.txt      > /tmp/test.txt
wc -l /tmp/train.txt /tmp/val.txt /tmp/test.txt

# 링크 생성 함수형 실행
link_split () {
    SPLIT=$1          # train / val / test
    LIST=$2
    while read -r img; do
        base=$(basename "$img" .jpg)
        ln -sf "$(realpath "$img")"                images/$SPLIT/$base.jpg
        [ -f "raw/$base.txt" ] && \
          ln -sf "$(realpath raw/$base.txt)"       labels/$SPLIT/$base.txt
    done < "$LIST"
}

link_split train /tmp/train.txt
link_split val   /tmp/val.txt
link_split test  /tmp/test.txt

Step 3. 결과 검증

ls images/train | wc -l          # 700
ls images/val   | wc -l          # 150
ls labels/train | wc -l          # 699 또는 700 (누락 라벨 반영)
ls -l images/train | head -3     # l 로 시작하는지 확인

du -sh raw images                # 링크라 images 는 거의 0

# 깨진 링크 찾기
find images labels -xtype l

find -xtype l 이 깨진 심볼릭 링크를 찾는 명령입니다. 교과 8·14에서 데이터를 옮긴 뒤 학습이 FileNotFoundError로 죽으면 여기부터 확인합니다.

실습 2-3 · 파이프로 라벨 통계 뽑기 (70분) ★핵심

배경

교과 8 목표 성능은 mAP@0.5 기준입니다. 그런데 클래스별 데이터가 심하게 불균형하면(예: 클래스 3이 5장뿐) 그 클래스의 AP는 거의 0이 되고 mAP 전체가 무너집니다. 학습 시작 전에 클래스 분포를 확인하는 것이 첫 번째 절차입니다.

Step 1. 라벨 파일 구조 확인

cd ~/kdt-linux/dataset/kimchi/raw
cat kimchi_0001.txt
# 출력 예: 3 0.512345 0.443210 0.150000 0.220000
#          └┬┘ └───┬──┘ └───┬──┘ └───┬──┘ └───┬──┘
#         class  x_center y_center  width   height   (전부 0~1 비율)

Step 2. 한 걸음씩 파이프 조립하기

# 1단계: 모든 라벨을 한 줄씩 모으기
cat *.txt | head -5

# 2단계: 첫 번째 필드(클래스)만 추출
cat *.txt | cut -d' ' -f1 | head -5

# 3단계: 정렬
cat *.txt | cut -d' ' -f1 | sort | head -5

# 4단계: 중복 개수 세기
cat *.txt | cut -d' ' -f1 | sort | uniq -c

# 5단계: 많은 순으로 정렬
cat *.txt | cut -d' ' -f1 | sort | uniq -c | sort -rn

한 줄씩 늘려가며 결과를 보는 것이 파이프 학습의 정석입니다. 처음부터 긴 명령을 외우려 하지 마십시오.

Step 3. 클래스 이름 붙여 리포트 만들기

cd ~/kdt-linux/dataset/kimchi

cat raw/*.txt | cut -d' ' -f1 | sort | uniq -c | sort -k2n > /tmp/counts.txt
cat /tmp/counts.txt

# classes.txt 와 결합
awk 'NR==FNR{name[$1]=$2; next} {printf "%-24s %5d\n", name[$2], $1}' \
    meta/classes.txt /tmp/counts.txt | tee meta/class_distribution.txt

출력 예:

leaf                       168
plastic_stone_metal        171
branch                     159
rubber_glove               165
disease_browning           172
green_onion_pepper         164

tee 는 화면에 보여주면서 동시에 파일로 저장합니다. > 만 쓰면 화면에 안 보입니다.

Step 4. 추가 통계 미션

M1. 총 객체(bbox) 개수는?

cat raw/*.txt | wc -l

M2. 이미지 1장당 평균 객체 수는?

echo "scale=2; $(cat raw/*.txt | wc -l) / $(ls raw/*.jpg | wc -l)" | bc

M3. 좌표가 0~1 범위를 벗어난 라벨을 찾으시오 ★

awk '{for(i=2;i<=5;i++) if($i<0 || $i>1) {print FILENAME": "$0; break}}' raw/*.txt
# 기대: kimchi_0456.txt 검출

M4. 정의되지 않은 클래스 ID를 쓰는 라벨을 찾으시오

MAXCLS=$(( $(wc -l < meta/classes.txt) - 1 ))
awk -v m=$MAXCLS '$1<0 || $1>m {print FILENAME": class="$1}' raw/*.txt
# 기대: kimchi_0456.txt class=9

M5. 빈 라벨 파일을 찾으시오

find raw -name "*.txt" -size 0
# 기대: kimchi_0789.txt

★ M6 (심화). bbox 면적이 전체 이미지의 1% 미만인 초소형 객체 개수는?

awk '$4*$5 < 0.01 {c++} END {print "tiny objects:", c+0}' raw/*.txt

초소형 객체는 YOLO에서 검출이 어렵습니다. 교과 8·14에서 mAP가 안 오를 때 이 통계를 먼저 확인합니다.

  • [ ] 클래스 분포 리포트를 파일로 저장했다

실습 2-4 · 아카이브와 백업 (50분)

Step 1. tar 기본

cd ~/kdt-linux/dataset/kimchi

tar -czvf /tmp/meta_backup.tar.gz meta/
ls -lh /tmp/meta_backup.tar.gz
tar -tzvf /tmp/meta_backup.tar.gz

mkdir -p /tmp/restore
tar -xzvf /tmp/meta_backup.tar.gz -C /tmp/restore
ls -R /tmp/restore

Step 2. 압축률 비교 실험

cd /tmp
tar -cf  raw_none.tar  ~/kdt-linux/dataset/kimchi/raw 2>/dev/null
tar -czf raw_gzip.tar.gz ~/kdt-linux/dataset/kimchi/raw 2>/dev/null
tar -cJf raw_xz.tar.xz   ~/kdt-linux/dataset/kimchi/raw 2>/dev/null
ls -lh raw_none.tar raw_gzip.tar.gz raw_xz.tar.xz

관찰: 텍스트(라벨)는 압축률이 매우 높고, JPG는 이미 압축되어 있어 거의 줄지 않습니다.

현업 시사점: 이미지 데이터셋은 압축해도 용량이 안 줄어듭니다. 전송할 때는 압축보다 rsync 증분 전송이 낫습니다.

Step 3. 제외 규칙

cd ~/kdt-linux
tar -czvf /tmp/project_backup.tar.gz \
    --exclude='*.jpg' \
    --exclude='*.pt' \
    --exclude='__pycache__' \
    --exclude='.git' \
    dataset/

이 --exclude 목록이 6일차 .gitignore의 예고편입니다. 코드와 메타데이터는 버전관리, 이미지·모델 가중치는 제외 — 이 원칙이 교과 7 이후 전 프로젝트의 규칙입니다.

Step 4. 날짜 자동 백업

cd ~/kdt-linux/dataset/kimchi
BACKUP_NAME="kimchi_meta_$(date +%Y%m%d_%H%M).tar.gz"
tar -czf "backup/$BACKUP_NAME" meta/
ls -lh backup/

Step 5. 실무 미션 — 백업 스크립트 초안

cd ~/kdt-linux
cat > backup_meta.sh << 'EOF'
#!/bin/bash
# 데이터셋 메타정보 백업 (이미지·모델 제외)
set -e
DS_ROOT=~/kdt-linux/dataset
STAMP=$(date +%Y%m%d_%H%M)

for ds in "$DS_ROOT"/*/; do
    name=$(basename "$ds")
    out="$ds/backup/${name}_meta_${STAMP}.tar.gz"
    mkdir -p "$ds/backup"
    tar -czf "$out" -C "$ds" meta 2>/dev/null && \
      echo "[OK] $out ($(du -h "$out" | cut -f1))"
done

# 30일 이상 된 백업 정리
find "$DS_ROOT" -name "*_meta_*.tar.gz" -mtime +30 -delete
echo "백업 완료: $STAMP"
EOF

chmod +x backup_meta.sh
./backup_meta.sh

4일차에 이 스크립트를 옵션 처리·로깅·에러 핸들링까지 갖춘 형태로 확장합니다.

✅ 체크포인트 2-4

  • [ ] tar czvf / xzvf / tzvf 를 각각 사용했다
  • [ ] --exclude 로 이미지를 제외한 백업을 만들었다
  • [ ] backup_meta.sh 가 정상 동작한다

cd ~/kdt-linux
history | tail -60 >> day2_history.txt
cat > DAY2.md << 'EOF'
# Day 2 — 권한 · 아카이브 · 텍스트 스트림
## 핵심 명령
- chmod 755/644/444, chown, 디렉토리 x 권한의 의미
- ln -s 로 용량 절약형 데이터셋 분할
- cat *.txt | cut -d' ' -f1 | sort | uniq -c | sort -rn
- tar czvf / xzvf / tzvf, --exclude
## 실무 연결
- raw/ 읽기전용 잠금 → 데이터 품질 평가 항목
- 클래스 분포 리포트 → 교과 8 mAP 사전 점검

과제

  1. chmod 600이 SSH 개인키에 필수인 이유를 조사해 3줄로 정리
  2. du -sh */ | sort -rh 를 /var 에 적용해 가장 큰 하위 디렉토리 3개 보고
  3. 다음 파이프의 각 단계가 무엇을 하는지 설명하시오 bash cat raw/*.txt | awk '{print $1}' | sort -n | uniq -c | awk '{print $2": "$1}'
  4. 내일 퀴즈 대비: > 와 >> 의 차이, 2>&1의 의미

강사 운영 노트

시점 주의사항
실습 2-1 Step4 디렉토리 x 권한 실험은 반드시 개별 실행시키십시오. 말로만 들으면 절대 이해 못 합니다.
실습 2-2 realpath 가 없으면 readlink -f 사용. WSL 환경에서 Windows 경로 마운트 시 심볼릭 링크 제약이 있을 수 있으므로 반드시 리눅스 파일시스템(~/) 안에서 실습.
실습 2-3 파이프를 한 번에 완성해 보여주지 말고 한 단계씩 결과를 보여주며 확장하십시오. 비전공자 이해도가 갈리는 지점입니다.
실습 2-4 압축률 비교에서 "JPG는 왜 안 줄어드는가"를 질문으로 던지면 이미지 압축(교과 3) 예고가 자연스럽습니다.
전체 chmod -R 777 을 만능 해결책으로 쓰는 습관이 생기지 않도록 초반에 강하게 경고하십시오.
