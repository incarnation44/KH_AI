8일차 · 부분 파이널 프로젝트 — `visionops` (4H)

visionops CLI 툴킷 구현 · 평가 루브릭 25점

56H 누적이 문서 4H전체 60H

실습 4H (이론 0H) 오늘의 한 문장: "지금까지 만든 것을 하나의 도구로 묶어, 포트폴리오에 올릴 수 있는 저장소를 완성한다."

1. 프로젝트 개요

1.1 무엇을 만드는가

visionops — Vision AI 프로젝트의 데이터셋 준비 전 과정을 자동화하는 CLI 툴킷

visionops init    <dataset_name>       # 표준 구조 생성
visionops check   <dataset_dir>        # 정합성 검증
visionops split   <dataset_dir>        # train/val/test 분할
visionops report  <dataset_dir>        # 통계 리포트 생성
visionops backup  <dataset_dir>        # 메타 백업
visionops run     <dataset_dir>        # 전체 파이프라인

1.2 왜 이걸 만드는가

관점 이유
교과 연계 교과 8·14·15 프로젝트에서 그대로 재사용
평가 연계 최종 평가 6개 항목 중 4개 항목의 사전 훈련
포트폴리오 취업 시 제시 가능한 실무형 산출물
역량 점검 안내서 교과 7 취지 — "훈련생이 본인의 역량 수준과 보완이 필요한 영역을 스스로 점검"

1.3 과정 전체 평가와의 매핑

최종 평가 항목 (안내서 5.3) 배점 본 프로젝트에서 훈련되는 것
프로젝트 완성도 30 요구 기능 구현 + 실행 검증
프로젝트 창의성 10 선택 기능(★) 구현
AI 모델 성능 20 (해당 없음 — 교과 8 이후)
코드 품질 10 함수화·문서화·커밋 히스토리
데이터 품질 10 검증 로직·리포트
프로젝트 수행 역량 20 일정·문서화·발표

2. 요구사항

2.1 필수 요구사항 (Must)

# 요구사항 근거
M1 단일 진입점 visionops 명령으로 6개 서브커맨드 제공 사용성

M6 report: 클래스 분포·bbox 통계·이상 데이터 요약 데이터 품질
M7 모든 실행이 logs/ 에 기록됨 추적성
M8 README.md 만 보고 다른 사람이 설치·실행 가능 문서화

2.2 선택 요구사항 (★ 창의성 배점)

# 기능 난이도
S1 --json 옵션으로 구조화 출력 (CI 파싱용) ★
S2 층화 분할(stratified split) 구현 ★★

5. 구현 가이드

5.1 메인 진입점 골격

#!/bin/bash
#===============================================================
# visionops — Vision AI 데이터셋 운영 툴킷
# 사용법: visionops <command> [args] [options]
#===============================================================
set -uo pipefail

readonly VERSION="1.0.0"
readonly SCRIPT_DIR="$(cd "$(dirname "${BASH_SOURCE[0]}")" && pwd)"
readonly LIB_DIR="$SCRIPT_DIR/lib"

source "$LIB_DIR/common.sh"

usage () {
    cat << EOF
visionops v$VERSION — Vision AI 데이터셋 운영 툴킷

사용법:
  visionops <command> [args] [options]

명령:
  init <name>          표준 데이터셋 구조 생성
  check <dir>          데이터셋 정합성 검증
  split <dir>          train/val/test 분할
  report <dir>         통계 리포트 생성
  backup <dir>         메타정보 백업
  run <dir>            전체 파이프라인 실행

전역 옵션:
  -h, --help           도움말
  -v, --version        버전
  -q, --quiet          최소 출력
  --log-dir <path>     로그 경로 (기본: ./logs)

각 명령의 상세 도움말:
  visionops <command> --help

예시:
  visionops init kimchi
  visionops check dataset/kimchi --min 500
  visionops split dataset/kimchi --ratio 70:15:15 --seed 42
  visionops run dataset/kimchi
EOF
}

main () {
    [ $# -eq 0 ] && { usage; exit 2; }

    case "$1" in
        -h|--help)     usage; exit 0 ;;
        -v|--version)  echo "visionops v$VERSION"; exit 0 ;;
        init)   shift; source "$LIB_DIR/cmd_init.sh";   cmd_init "$@" ;;
        check)  shift; source "$LIB_DIR/cmd_check.sh";  cmd_check "$@" ;;
        split)  shift; source "$LIB_DIR/cmd_split.sh";  cmd_split "$@" ;;
        report) shift; source "$LIB_DIR/cmd_report.sh"; cmd_report "$@" ;;
        backup) shift; source "$LIB_DIR/cmd_backup.sh"; cmd_backup "$@" ;;
        run)    shift; source "$LIB_DIR/cmd_run.sh";    cmd_run "$@" ;;
        *) echo "알 수 없는 명령: $1" >&2; usage; exit 2 ;;
    esac
}

main "$@"

5.2 공통 라이브러리

# lib/common.sh
#===============================================================
# 공통 함수 — 로깅, 색상, 유틸리티
#===============================================================

readonly C_RED='\033[0;31m'
readonly C_GRN='\033[0;32m'
readonly C_YEL='\033[0;33m'
readonly C_BLU='\033[0;34m'
readonly C_NC='\033[0m'

LOG_DIR="${LOG_DIR:-./logs}"
QUIET="${QUIET:-0}"

_ts () { date '+%Y-%m-%d %H:%M:%S'; }

_write_log () {
    mkdir -p "$LOG_DIR"
    echo "[$(_ts)] $*" >> "$LOG_DIR/visionops.log"
}

log ()  { [ "$QUIET" -eq 1 ] || echo "  $*";                    _write_log "INFO  $*"; }
ok ()   { [ "$QUIET" -eq 1 ] || echo -e "  ${C_GRN}[OK]${C_NC}   $*";  _write_log "OK    $*"; }
warn () { echo -e "  ${C_YEL}[WARN]${C_NC} $*" >&2;             _write_log "WARN  $*"; }
fail () { echo -e "  ${C_RED}[FAIL]${C_NC} $*" >&2;             _write_log "FAIL  $*"; }
die ()  { fail "$*"; exit 1; }

section () {
    [ "$QUIET" -eq 1 ] && return
    echo ""
    echo -e "${C_BLU}[$1]${C_NC} $2"
}

banner () {
    [ "$QUIET" -eq 1 ] && return
    echo "══════════════════════════════════════════════"
    echo "  $1"
    echo "  $(_ts)"
    echo "══════════════════════════════════════════════"
}

require_dir () { [ -d "$1" ] || die "디렉토리 없음: $1"; }
require_cmd () { command -v "$1" >/dev/null 2>&1 || die "명령 없음: $1"; }

count_files () { find "$1" -maxdepth 1 -name "$2" 2>/dev/null | wc -l; }

5.3 서브커맨드 예시 — cmd_init.sh

# lib/cmd_init.sh
cmd_init_usage () {
    cat << EOF
사용법: visionops init <name> [옵션]

인자:
  name              데이터셋 이름

옵션:
  --root <path>     생성 위치 (기본: ./dataset)
  --classes <n>     클래스 수 (기본: 5)
  -h, --help
EOF
}

cmd_init () {
    local NAME="" ROOT="./dataset" NCLS=5

    [ $# -eq 0 ] && { cmd_init_usage; exit 2; }
    NAME="$1"; shift
    while [ $# -gt 0 ]; do
        case "$1" in
            --root)    shift; ROOT="$1" ;;
            --classes) shift; NCLS="$1" ;;
            -h|--help) cmd_init_usage; exit 0 ;;
            *) die "알 수 없는 옵션: $1" ;;
        esac
        shift
    done

    local DS="$ROOT/$NAME"
    banner "visionops init :: $NAME"

    [ -d "$DS" ] && die "이미 존재: $DS"

    section 1 "디렉토리 생성"
    mkdir -p "$DS"/raw/{images,labels}
    mkdir -p "$DS"/{images,labels}/{train,val,test}
    mkdir -p "$DS"/{processed,meta,backup}
    ok "구조 생성 완료"

    section 2 "메타 파일 생성"
    : > "$DS/meta/classes.txt"
    for i in $(seq 0 $((NCLS-1))); do
        echo "$i class_$i" >> "$DS/meta/classes.txt"
    done
    ok "classes.txt (${NCLS}종)"

    cat > "$DS/meta/data.yaml" << EOF
path: $(readlink -f "$DS")
train: images/train
val: images/val
test: images/test
nc: $NCLS
names:
$(awk '{printf "  %s: %s\n", $1, $2}' "$DS/meta/classes.txt")
EOF
    ok "data.yaml"

    cat > "$DS/meta/DATASET.md" << EOF
# $NAME Dataset

| 항목 | 내용 |
|---|---|
| 생성일 | $(date +%Y-%m-%d) |
| 클래스 수 | $NCLS |
| 라벨 포맷 | YOLO (class x_center y_center width height, 0~1) |
| 분할 | train : val : test = 7 : 1.5 : 1.5 |

## 수집 조건
(작성 필요)

## 사용 제한
(㈜비솔 제공 데이터인 경우: 원내 폐쇄망 전용, 외부 업로드 금지)

## 주의사항
- raw/ 는 읽기 전용
- 전처리는 processed/ 에서 수행
EOF
    ok "DATASET.md"

    section 3 "완료"
    log "생성 위치: $DS"
    log "다음 단계: raw/images, raw/labels 에 데이터를 배치한 후"
    log "           visionops check $DS"
    return 0
}

나머지 서브커맨드는 4일차 dataset_check.sh, 5일차 split_dataset.sh, 2·3일차 리포트 로직을 함수로 이식하면 됩니다. 새로 짜는 것이 아니라 리팩터링입니다.

5.4 테스트 스크립트

# tests/test_basic.sh
#!/bin/bash
set -uo pipefail
cd "$(dirname "$0")/.."

PASS=0; FAIL=0
t () {
    local name="$1"; shift
    if "$@" > /dev/null 2>&1; then
        echo "  [PASS] $name"; PASS=$((PASS+1))
    else
        echo "  [FAIL] $name"; FAIL=$((FAIL+1))
    fi
}
t_exit () {
    local name="$1" expect="$2"; shift 2
    "$@" > /dev/null 2>&1
    local rc=$?
    if [ "$rc" -eq "$expect" ]; then
        echo "  [PASS] $name (exit=$rc)"; PASS=$((PASS+1))
    else
        echo "  [FAIL] $name (expect=$expect got=$rc)"; FAIL=$((FAIL+1))
    fi
}

echo "== visionops 기본 테스트 =="
t       "help 출력"        ./visionops --help
t       "version 출력"     ./visionops --version
t_exit  "인자 없음 → 2"     2  ./visionops
t_exit  "잘못된 명령 → 2"   2  ./visionops nosuchcmd
t       "init 실행"        ./visionops init _testds --root /tmp/_vo
t       "check 실행"       ./visionops check /tmp/_vo/_testds --min 0
rm -rf /tmp/_vo

echo ""
echo "  통과 $PASS / 실패 $FAIL"
[ "$FAIL" -eq 0 ]
