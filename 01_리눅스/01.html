PART 1. 이론 (3H)

1교시 · 왜 리눅스인가 (50분)

1.1 이 과정에서 리눅스를 안 배우면 생기는 일

이 과정의 최종 산출물 2종이 어디에서 돌아가는지 먼저 봅니다.

최종 산출물 실행 환경 OS
교과 14 · 조각김치 이물검출 NVIDIA Jetson Orin Nano Super Linux (JetPack/Ubuntu)
교과 13 · OnDevice 실습 Raspberry Pi Linux (Raspberry Pi OS)
교과 5·8·10·11 모델 학습 AWS g5.xlarge 클라우드 GPU Linux (Ubuntu)

세 곳 모두 모니터도 마우스도 없습니다. 접속하면 검은 화면에 커서 하나만 깜빡입니다. 즉 리눅스 CLI는 "선택 과목"이 아니라 이 과정의 결과물을 만지는 유일한 인터페이스입니다.

1.2 리눅스의 구조

   [ 사용자 ]
        │
   ┌────▼─────┐
   │   셸 (Shell)     │  ← 우리가 명령을 입력하는 곳. bash / zsh
   └────┬─────┘
        │  시스템 콜
   ┌────▼─────┐
   │  커널 (Kernel)   │  ← 하드웨어 자원(CPU·메모리·디스크·GPU) 관리
   └────┬─────┘
        │
   [ 하드웨어 ]
  • 커널: 리누스 토르발스가 1991년 공개. 우리가 직접 만질 일은 거의 없음
  • 배포판(Distribution): 커널 + 각종 도구 + 패키지 관리자를 묶은 완제품
  • Ubuntu (Debian 계열, apt) ← 본 과정 사용
  • CentOS/Rocky (RedHat 계열, dnf)
  • Raspberry Pi OS (Debian 계열) ← 교과 13
  • JetPack (Ubuntu 기반) ← 교과 14 Jetson
  • LTS(Long Term Support): 22.04 LTS는 2027년까지 보안 업데이트 제공. 그래서 딥러닝 프레임워크 공식 지원 대상이 됩니다.

현업 포인트 PyTorch·TensorRT·JetPack 공식 문서는 대부분 Ubuntu LTS 버전을 기준으로 설치 가이드를 제공합니다. 교과 14에서 TensorRT를 Jetson에 올릴 때, 여러분이 참고할 문서는 100% 리눅스 명령어로 쓰여 있습니다.

1.3 셸과 터미널

용어 의미 비유
터미널(Terminal) 셸을 띄우는 창 자동차의 운전석
셸(Shell) 명령을 해석해 커널에 전달하는 프로그램 핸들·페달
bash 가장 널리 쓰이는 셸. Ubuntu 기본 표준 핸들

1.4 프롬프트 읽기

kdt@vision-ai:~/dataset$
└┬┘ └───┬────┘ └───┬──┘└┬┘
 │      │          │    └── 권한 표시: $ = 일반 사용자, # = root
 │      │          └─────── 현재 작업 디렉토리 (~ 는 홈 디렉토리)
 │      └────────────────── 호스트(컴퓨터) 이름
 └───────────────────────── 로그인 사용자 이름

원격 서버 여러 대를 동시에 다루는 교과 13·14에서 "내가 지금 어느 장비의 어느 폴더에 있는가" 를 프롬프트로 확인하지 못하면 라즈베리파이에 지울 파일을 학습 서버에서 지우는 사고가 납니다.

2교시 · 파일 시스템 계층 (FHS) (50분)

2.1 윈도우와 근본적으로 다른 점

Windows Linux
최상위 C:\, D:\ 드라이브별로 분리 / 하나 (모든 것이 여기서 시작)
경로 구분자 \ (역슬래시) / (슬래시)
대소문자 구분 안 함 (Data = data) 구분함 (Data ≠ data)
확장자 파일 종류를 결정 단순 이름의 일부
외장 디스크 E:\ 로 붙음 /mnt/외장 처럼 트리 안에 마운트

사고 사례: 훈련생이 Images/ 폴더를 만들고 코드에서는 images/를 참조 → Windows에서는 동작, Jetson에 올리면 FileNotFoundError. 교과 14 배포 단계 단골 오류입니다.

2.2 주요 디렉토리

/
├── bin      기본 명령어 실행 파일 (ls, cp, mv ...)
├── etc      시스템 설정 파일 (텍스트) ★
├── home     사용자별 홈 디렉토리 ★★★  /home/kdt
├── root     root 계정 전용 홈
├── usr      설치된 응용 프로그램 (/usr/local/ 에 직접 설치한 것)
├── var      가변 데이터 — 로그(/var/log) ★
├── tmp      임시 파일 (재부팅 시 삭제)
├── opt      선택적 대형 패키지 (Anaconda 설치 위치로 자주 쓰임)
├── mnt      외부 저장소 마운트 지점 ★ (대용량 데이터셋 디스크)
├── media    자동 마운트 (USB 등)
├── dev      장치 파일 — 카메라가 /dev/video0 로 보임 ★★
└── proc     커널/프로세스 정보 (가상 파일시스템)

★ 표시가 이 과정에서 실제로 만질 곳입니다.

  • /dev/video0 — 교과 14 Daheng 카메라, 교과 15 웹캠이 여기로 잡힙니다. OpenCV의 cv2.VideoCapture(0)이 이 파일을 엽니다.
  • /mnt/data — 수천 장 데이터셋은 홈이 아니라 별도 디스크에 마운트해 두는 것이 현업 표준입니다.
  • /var/log — 학습 중 죽은 프로세스의 원인을 찾는 곳.

2.3 절대경로 vs 상대경로

# 절대경로 — / 에서 시작. 어디서 실행하든 같은 곳을 가리킴
/home/kdt/dataset/kimchi/images/train/img_0001.jpg

# 상대경로 — 현재 위치 기준
./images/train/img_0001.jpg      # . = 현재 디렉토리
../labels/train/img_0001.txt     # .. = 상위 디렉토리
~/dataset/kimchi                 # ~ = 내 홈 디렉토리

현업 규칙: 학습 스크립트에 절대경로를 하드코딩하면 다른 사람 PC나 Jetson에서 그대로 깨집니다. 코드에는 상대경로 또는 설정파일 변수, 실행 명령에는 절대경로 — 이 원칙은 교과 8·14 코드 리뷰에서 매번 지적되는 항목입니다.

3교시 · 명령어의 문법과 도움말 (50분)

3.1 명령어 3요소

   ls        -l -a        /home/kdt
   └┬┘       └──┬──┘       └───┬────┘
  명령어      옵션          인자
             (-단축, --전체)   (대상)

ls -l -a          # 따로 쓰기
ls -la            # 붙여 쓰기 (동일)
ls --all          # 긴 옵션

3.2 모르는 명령어를 만났을 때 (가장 중요한 기술)

man ls          # 매뉴얼 (q 로 종료, / 로 검색)
ls --help       # 간단 도움말 (더 자주 씀)
tldr ls         # 예제 위주 (설치 필요: sudo apt install tldr)
which python    # 이 명령어의 실제 위치
type cd         # 내장 명령인지 외부 명령인지

강사 멘트: "앞으로 6개월간 처음 보는 명령어를 수십 개 만납니다. 외우는 게 목표가 아니라 --help를 읽고 5분 안에 쓸 수 있게 되는 것이 목표입니다."

3.3 오늘 쓸 명령어 지도

분류 명령어
위치 pwd cd
조회 ls tree stat file
생성 mkdir touch
복사·이동 cp mv
삭제 rm rmdir
보기 cat head tail less
검색 find wc
시스템 whoami df du uname

3.4 위험 명령어 사전 경고 ⚠️

rm -rf /            # 시스템 전체 삭제 — 절대 금지
rm -rf ~            # 홈 전체 삭제
rm -rf * .          # 공백 하나로 재앙

안전 규칙 3가지 1. rm 전에 반드시 ls로 대상 확인 2. 처음에는 rm -i (확인 프롬프트) 사용 3. 데이터셋 폴더는 chmod -w 로 쓰기 잠금 (2일차)

실습 1-1 · 터미널 첫 걸음 (40분)

Step 1. 위치 파악하기

pwd                   # 현재 위치 출력
cd /                  # 최상위로 이동
pwd
ls                    # 최상위에 뭐가 있나
cd ~                  # 홈으로 복귀
pwd

Step 2. ls 옵션 완전 정복

ls                    # 기본
ls -l                 # 상세 (long)
ls -a                 # 숨김 파일 포함 (all) — .으로 시작하는 파일
ls -la                # 둘 다
ls -lh                # 크기를 KB/MB로 (human readable)
ls -lt                # 수정시간 최신순
ls -ltr               # 수정시간 오래된순 (r = reverse)
ls -lS                # 크기순

Step 3. ls -l 출력 해독하기 ★

-rw-r--r--  1  kdt  kdt   4096  Aug 26 09:15  img_0001.jpg
└────┬───┘  │  └┬┘  └┬┘   └─┬┘  └─────┬────┘  └─────┬────┘
   ①권한    ②  ③소유자 ④그룹 ⑤크기     ⑥수정시각      ⑦이름
             링크수

① 첫 글자: - 일반파일 / d 디렉토리 / l 심볼릭링크 ① 나머지 9자리: 소유자(rwx) 그룹(rwx) 기타(rwx) → 2일차에서 상세히 다룸

확인 미션: 아래 3개를 각각 실행하고 첫 글자가 무엇인지 답하시오.

ls -ld /home          # → ?
ls -l /bin/ls         # → ?
ls -ld /bin           # → ?  (힌트: Ubuntu에서 /bin은 링크입니다)

Step 4. 디렉토리 이동 단축키

cd /home/kdt/         # 절대경로
cd ..                 # 한 단계 위
cd ../..              # 두 단계 위
cd -                  # 직전 디렉토리로 (토글)
cd                    # 인자 없으면 홈으로

Tab 자동완성 훈련 (매우 중요)

cd /ho[Tab]           # → /home/ 자동완성
cd /home/k[Tab]       # → /home/kdt/
ls /et[Tab][Tab]      # 후보 목록 표시

실무에서 파일명이 img_20260826_143052_cam01.jpg 같은 형태입니다. Tab 없이는 못 삽니다.

실습 1-3 · Vision AI 데이터셋 폴더 구조 만들기 (60분) ★핵심

배경

교과 8에서 ㈜비솔이 제공하는 조각김치·이물 데이터는 JPG 약 1,000장 + 라벨 TXT입니다. 교과 14에서는 훈련생이 컨베이어에서 최소 500장을 직접 촬영합니다. 이 파일들을 어디에 어떻게 두는지가 프로젝트 성패를 가릅니다.

Step 1. 표준 구조 설계

YOLO 계열 학습 프레임워크가 기대하는 표준 레이아웃입니다.

~/kdt-linux/dataset/kimchi/
├── raw/                    원본 (절대 수정 금지)
├── images/
│   ├── train/              70%
│   ├── val/                15%
│   └── test/               15%
├── labels/
│   ├── train/
│   ├── val/
│   └── test/
├── meta/
│   ├── classes.txt         클래스 이름 목록

Step 4. 더미 데이터셋 1,000장 생성

실데이터는 9월 중순 제공 예정이므로, 구조가 동일한 더미 데이터로 먼저 훈련합니다.

아래 내용을 입력합니다. (직접 타이핑 — 오늘의 마지막 타이핑 훈련)

#!/bin/bash
# make_sample_dataset.sh
# 교과 8/14 실데이터와 동일한 구조의 더미 데이터셋 생성
set -e

ROOT=~/kdt-linux/dataset/kimchi
N=1000

mkdir -p "$ROOT/raw"
cd "$ROOT/raw"

echo "[1/3] 이미지 $N 장 생성 중..."
for i in $(seq -w 1 $N); do
    # 실제 이미지 대신 최소 크기 JPG 헤더 + 더미 바이트
    printf '\xff\xd8\xff\xe0dummy-jpeg-%s' "$i" > "kimchi_${i}.jpg"
done

echo "[2/3] 라벨 TXT 생성 중..."
for i in $(seq -w 1 $N); do
    CLS=$(( RANDOM % 6 ))
    X=$(awk -v s=$RANDOM 'BEGIN{srand(s);printf "%.6f", rand()}')
    Y=$(awk -v s=$RANDOM 'BEGIN{srand(s);printf "%.6f", rand()}')
    W=$(awk -v s=$RANDOM 'BEGIN{srand(s);printf "%.6f", rand()*0.3+0.05}')
    H=$(awk -v s=$RANDOM 'BEGIN{srand(s);printf "%.6f", rand()*0.3+0.05}')
    echo "$CLS $X $Y $W $H" > "kimchi_${i}.txt"
done

echo "[3/3] 의도적 오류 데이터 주입 (검증 실습용)..."
rm -f kimchi_0007.txt                       # 라벨 누락
rm -f kimchi_0123.jpg                       # 이미지 누락
echo "9 1.500000 0.400000 0.200000 0.200000" > kimchi_0456.txt  # 범위 초과 + 없는 클래스
> kimchi_0789.txt                           # 빈 파일
touch "kimchi 0999.jpg"                     # 파일명에 공백

echo "완료: $(ls *.jpg | wc -l) 이미지 / $(ls *.txt | wc -l) 라벨"

실행:

chmod +x make_sample_dataset.sh
./make_sample_dataset.sh

chmod +x 는 "실행 권한 부여"입니다. 자세한 원리는 2일차에.

Step 3. 실무 미션 — 정합성 1차 점검

미션 A. 라벨이 없는 이미지 찾기

cd ~/kdt-linux/dataset/kimchi/raw

# 이미지 목록과 라벨 목록을 각각 확장자 뗀 형태로 저장
ls *.jpg | sed 's/\.jpg$//' | sort > /tmp/imgs.txt
ls *.txt | sed 's/\.txt$//' | sort > /tmp/lbls.txt

# 차집합 = 라벨 없는 이미지
comm -23 /tmp/imgs.txt /tmp/lbls.txt

# 반대: 이미지 없는 라벨
comm -13 /tmp/imgs.txt /tmp/lbls.txt

기대 결과: kimchi_0007 (라벨 없음), kimchi_0123 (이미지 없음), kimchi 0999 (공백 파일명)

왜 이게 중요한가: YOLO 학습 시 라벨 없는 이미지는 "객체가 하나도 없는 배경 이미지"로 학습됩니다. 의도치 않은 배경 학습은 교과 8·14에서 mAP를 떨어뜨리는 대표 원인입니다. 목표 성능이 mAP@0.5 ≥ 0.7 이므로 이 점검은 필수 절차입니다.

미션 B. 공백 파일명 정리

mv "kimchi 0999.jpg" "kimchi_0999.jpg"
find . -name "* *"        # 이제 아무것도 안 나와야 함

★ 심화 미션 (전공자): 공백 파일명이 여러 개일 때 한 번에 바꾸는 명령을 작성하시오.

find . -name "* *" -type f | while read -r f; do
    mv "$f" "$(echo "$f" | tr ' ' '_')"
done

cp 유용 옵션

옵션 의미
-r 디렉토리 재귀 복사
-p 타임스탬프·권한 보존
-v 진행 상황 출력
-n 기존 파일 덮어쓰지 않음
-a -rp + 링크 보존 (아카이브)

Step 2. 데이터셋 원본 보호 ⚠️

현업 규칙: raw/는 절대 손대지 않습니다. 모든 전처리는 복사본에서 합니다. 원본을 덮어쓴 순간 그 데이터셋은 재현 불가능해지고, 평가항목 「데이터 품질」에서 감점됩니다.

Step 3. 원격 접속 (SSH)

# SSH 클라이언트 확인
ssh -V

# 강사 서버 또는 AWS 인스턴스 접속 (강사 안내 주소 사용)
ssh 사용자명@서버주소
# 예: ssh kdt@192.168.0.10

Windows에서 MobaXterm 사용 시 1. Session → SSH 2. Remote host: 강사 안내 IP 3. Specify username 체크 후 계정 입력 4. OK → 비밀번호 입력 5. 좌측 SFTP 패널에서 드래그로 파일 전송 가능

Step 4. 파일 전송 — scp / rsync

# 로컬 → 원격
scp meta/classes.txt kdt@서버주소:~/

# 원격 → 로컬
scp kdt@서버주소:~/classes.txt /tmp/

# 폴더 전송
scp -r meta kdt@서버주소:~/

# rsync — 변경분만 전송 (대용량 데이터셋 필수) ★
rsync -avh --progress images/ kdt@서버주소:~/images/
rsync 옵션 의미
-a 아카이브 (권한·시간 보존, 재귀)
-v 상세 출력
-h 사람이 읽기 좋은 크기
--progress 진행률
--dry-run 실제로 전송 안 하고 시뮬레이션 (항상 먼저 실행)

왜 rsync인가: 이미지 1,000장을 학습 서버에 올렸는데 50장만 수정했다면, scp는 1,000장을 다시 보내고 rsync는 50장만 보냅니다. 교과 5·8의 AWS 클라우드 학습에서 시간과 비용이 직접 차이납니다.

⚠️ 보안 주의: ㈜비솔 제공 실데이터는 원내 폐쇄망 전용입니다. 외부 클라우드로의 rsync/scp 전송은 금지되며, 개인별 보안서약서 대상입니다(안내서 6.2절·7장). 오늘 실습은 더미 데이터로만 수행합니다.
