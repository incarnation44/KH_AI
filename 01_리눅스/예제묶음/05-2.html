명령어 연습 부록 — conda create · install · list/env · pip 각 20제

쉬운 예제 10개 → 어려운 예제 10개 순서로, 환경 관리 명령이 손에 익도록 반복 연습합니다

이 문서의 목표: D5에서 배운 conda·pip 명령이 "낯선 도구"에서 "손에 익은 습관"이 되도록, 아주 쉬운 예제부터 실무에 가까운 예제까지 단계적으로 반복 연습합니다.

이 문서를 보는 법

  • 각 명령어마다 쉬움 10개 → 어려움 10개 순서로 배치되어 있습니다. 쉬움부터 순서대로 직접 타이핑해 보세요.
  • $로 시작하는 줄이 "내가 입력하는 명령"이고, 그 아래 줄이 예상 결과입니다. 버전 번호(예: numpy 1.26.4)는 실습 시점에 따라 실제로는 다르게 나올 수 있습니다 — 형태만 봐 주세요.
  • 각 예제 아래 의미가 "이 명령이 왜 이렇게 동작하는지"를 설명합니다.
  • 패키지를 실제로 설치하는 예제는 시간이 걸리거나 용량을 차지할 수 있으니, 이미 만들어둔 vision-ai 환경을 더럽히고 싶지 않다면 이 문서 전용 연습 환경을 하나 새로 만들어 진행해도 좋습니다.
  • 막히면 D5 본문(05.html)의 해당 절로 돌아가 개념을 다시 확인하세요.
# 이 문서 전용 연습 환경 (선택사항)
conda create -n cmd-practice-05 python=3.10 -y
conda activate cmd-practice-05

1. conda create — 새로운 환경 만들기

conda create는 프로젝트마다 독립된 파이썬 작업 공간(가상환경)을 새로 만드는 명령입니다. 한 환경에서 패키지를 바꿔도 다른 환경에는 영향이 없습니다.

conda create · 쉬움 10제

  1. $ conda create -n myenv
...
Proceed ([y]/n)? y
...
#
# To activate this environment, use
#     $ conda activate myenv

    의미: -n(name) 뒤에 이름을 주면 그 이름의 새 가상환경을 만듭니다. 아직 패키지를 지정하지 않아 거의 빈 환경이 만들어집니다.

  2. $ conda create -n vision-ai python=3.10
...
# To activate this environment, use
#     $ conda activate vision-ai

    의미: python=버전을 붙이면 그 버전의 파이썬이 포함된 환경을 만듭니다. 프로젝트마다 다른 파이썬 버전을 쓸 때 필수입니다.

  3. $ conda create -n test-env python=3.10 numpy pandas
...
The following NEW packages will be INSTALLED:
  numpy   pkgs/main/...
  pandas  pkgs/main/...
  python  pkgs/main/3.10...

    의미: 환경 생성과 동시에 여러 패키지를 나열해 한 번에 설치할 수 있습니다.

  4. $ conda create -y -n quick-env python=3.10
(확인 질문 없이 바로 설치 진행)

    의미: -y는 "무조건 예"로 답하고 넘어가겠다는 옵션입니다. 스크립트 자동화에 필수입니다.

  5. $ conda env list
# conda environments:
#
base                  *  /home/kdt/anaconda3
vision-ai                /home/kdt/anaconda3/envs/vision-ai
myenv                    /home/kdt/anaconda3/envs/myenv

    의미: 지금까지 만든 모든 환경 목록을 보여줍니다. *는 현재 활성화된 환경 표시입니다.

  6. $ conda activate vision-ai
(vision-ai) $

    의미: 해당 환경으로 전환합니다. 이후 설치하는 패키지는 이 환경 안에만 적용됩니다.

  7. (vision-ai) $ conda deactivate
$

    의미: 현재 환경에서 빠져나와 이전(보통 base) 환경으로 돌아갑니다.

  8. $ conda create -n copy-env --clone vision-ai
(vision-ai 환경과 동일한 구성의 copy-env 생성)

    의미: --clone 기존환경이름은 그 환경을 그대로 복제한 새 환경을 만듭니다. 실험 전 백업용으로 씁니다.

  9. $ conda remove -n test-env --all
Remove all packages in environment .../test-env:
Proceed ([y]/n)? y

    의미: --all은 그 환경 안의 모든 패키지와 환경 자체를 통째로 지웁니다.

  10. $ conda create -n edge-ai python=3.9 -c conda-forge
(conda-forge 채널에서 패키지를 받아와 환경 생성)

    의미: -c 채널이름은 기본 채널이 아닌 다른 저장소(채널)에서 패키지를 받아오게 합니다. conda-forge는 가장 널리 쓰이는 커뮤니티 채널입니다.

conda create · 어려움 10제

  1. $ conda create -n exp001 python=3.10 pytorch torchvision -c pytorch
(pytorch 공식 채널에서 GPU 지원 패키지들이 설치됨)

    의미: 특정 라이브러리는 공식 채널(-c pytorch)에서 받아야 최신·정확한 빌드가 설치됩니다.

  2. $ conda env create -f environment.yml
(yml에 정의된 이름·채널·패키지 그대로 환경이 재현됨)

    의미: env create -f는 yml 파일 안에 적힌 환경 이름·채널까지 전부 반영합니다 — 팀 표준 재현 방식입니다.

  3. $ conda create -n gpu-test python=3.10 cudatoolkit=11.8 -c nvidia
(CUDA 툴킷까지 포함된 환경 생성)

    의미: 특정 CUDA 버전을 지정해 GPU 드라이버와 호환되는 조합을 명시적으로 맞출 수 있습니다.

  4. $ conda create -n minimal-env --no-default-packages python=3.10
(기본 부가 패키지 없이 정말 최소 구성만 설치됨)

    의미: --no-default-packages는 필요한 것만 나중에 하나씩 설치하고 싶을 때, 처음부터 깨끗한 환경을 만드는 옵션입니다.

  5. $ conda create -n offline-env python=3.10 --offline
(인터넷 연결 없이, 로컬에 캐시된 패키지만으로 환경 생성 시도)

    의미: --offline은 네트워크가 불안정한 강의장·서버에서 이미 받아둔 패키지 캐시만으로 환경을 만들 때 씁니다.

  6. $ CONDA_PKGS_DIRS=/data/conda-pkgs conda create -n big-env python=3.10
(패키지 캐시가 기본 위치가 아닌 /data/conda-pkgs에 저장되며 환경 생성)

    의미: 환경변수로 conda의 캐시 저장 위치를 바꿀 수 있습니다. 홈 디렉토리 용량이 부족한 서버에서 유용합니다.

  7. $ conda create -n exp$(date +%m%d) python=3.10
(예: exp0902 처럼 날짜가 이름에 자동으로 들어간 환경 생성)

    의미: 셸 명령치환($())을 환경 이름에 활용하면 실험할 때마다 날짜별로 환경을 자동 구분할 수 있습니다.

  8. $ conda create -n prod-copy --clone vision-ai --copy
(원본과 파일을 공유하지 않고 전부 실제로 복사된 독립 환경 생성)

    의미: 기본 --clone은 일부 파일을 링크로 공유할 수 있는데, --copy를 추가하면 원본과 완전히 분리된 독립 사본을 만듭니다(배포용 이미지에 적합).

  9. $ conda create -n research python=3.10 --dry-run
(실제로 설치하지 않고, 만약 만든다면 어떤 패키지가 들어갈지만 미리 보여줌)

    의미: --dry-run은 진짜 생성 전에 무엇이 설치될지 시뮬레이션만 해보는 안전한 확인 옵션입니다.

  10. $ conda list --revisions
rev 0  2026-08-20 09:00  (최초 생성)
rev 1  2026-08-20 09:05  +numpy-1.26.4

    의미: conda는 환경의 모든 변경을 기록해 두어서, 나중에 conda install --revision 번호로 특정 시점 상태로 되돌릴 수 있습니다.

2. conda install — 환경 안에 패키지 설치하기

이미 만들어진 환경에 필요한 라이브러리를 추가할 때 씁니다. numpy, pandas, opencv 같은 패키지가 이 명령으로 설치됩니다.

conda install · 쉬움 10제

  1. $ conda install numpy
The following NEW packages will be INSTALLED:
  numpy  pkgs/main/...
Proceed ([y]/n)? y

    의미: 현재 활성화된 환경에 numpy를 설치합니다. 환경을 지정하지 않으면 지금 켜져 있는 환경에 설치됩니다.

  2. $ conda install -y pandas
(확인 질문 없이 바로 설치)

    의미: -y로 자동 승인합니다.

  3. $ conda install numpy=1.26
(정확히 1.26 버전의 numpy 설치)

    의미: =버전을 붙이면 그 버전을 정확히 지정해서 설치합니다.

  4. $ conda install numpy pandas matplotlib
(세 패키지가 한 번에 설치)

    의미: 여러 패키지를 공백으로 나열하면 한 번의 명령으로 전부 설치됩니다.

  5. $ conda install -n vision-ai opencv
(지금 활성화 여부와 상관없이 vision-ai 환경에 opencv 설치됨)

    의미: -n 환경이름을 지정하면 그 환경에 직접 설치할 수 있습니다(활성화하지 않아도 됩니다).

  6. $ conda install -c conda-forge opencv
(conda-forge 채널에서 opencv 설치)

    의미: 기본 채널에 없거나 버전이 오래된 패키지는 -c로 다른 채널을 지정해 받습니다.

  7. $ conda install --dry-run pytorch
(실제로 설치하지 않고 "설치될 예정" 목록만 미리 보여줌)

    의미: --dry-run은 진짜 설치 전에 무엇이 바뀔지 시뮬레이션만 해보는 안전한 확인 옵션입니다.

  8. $ conda update numpy
(numpy가 최신 버전으로 업그레이드됨)

    의미: install 대신 update를 쓰면 이미 설치된 패키지를 최신 버전으로 올립니다.

  9. $ conda install jupyter
(주피터 노트북 관련 패키지들이 함께 설치됨)

    의미: 하나의 이름(jupyter)이 사실 여러 개의 연관 패키지 묶음을 가리키는 경우가 많습니다.

  10. $ conda list numpy
numpy   1.26.4   py310h...

    의미: 설치가 잘 되었는지 확인할 때 conda list 뒤에 이름을 붙이면 그 패키지만 검색해서 보여줍니다.

conda install · 어려움 10제

  1. $ conda install numpy=1.24 --no-deps
(의존 패키지 버전을 건드리지 않고 numpy만 딱 1.24로 설치)

    의미: --no-deps는 "의존 패키지는 건드리지 말고 이 패키지만" 설치할 때 씁니다. 의존성이 깨질 수 있어 신중하게 사용해야 합니다.

  2. $ conda install "numpy>=1.20,<1.25"
(1.20 이상 1.25 미만 범위 안에서 conda가 알아서 버전을 골라 설치)

    의미: 부등호로 버전 범위를 지정할 수 있습니다. 다른 라이브러리와의 호환성 때문에 범위 제한이 필요할 때 씁니다.

  3. $ conda install --freeze-installed opencv
(기존에 설치된 다른 패키지들의 버전은 그대로 유지한 채 opencv만 추가)

    의미: --freeze-installed는 새 패키지를 넣을 때 기존 환경을 최대한 안 건드리도록 강제합니다. "잘 되던 환경이 깨지는" 사고를 예방합니다.

  4. $ conda install -c pytorch -c nvidia pytorch torchvision pytorch-cuda=11.8
(여러 채널을 우선순위대로 참고해 GPU용 pytorch 세트가 설치됨)

    의미: -c를 여러 번 쓰면 앞에 쓴 채널을 더 우선해서 찾습니다. 공식 조합 설치 명령은 실제로 이렇게 여러 채널을 지정하는 경우가 많습니다.

  5. $ conda install --file requirements.txt
(텍스트 파일에 한 줄씩 적힌 패키지들이 순서대로 설치됨)

    의미: 명령줄에 일일이 나열하지 않고 파일로 관리된 패키지 목록을 그대로 설치에 활용합니다.

  6. $ conda install numpy --channel-priority strict
(여러 채널 중 우선순위가 명확한 채널의 패키지만 엄격히 선택되어 설치됨)

    의미: 채널이 여러 개일 때 서로 다른 채널의 패키지가 섞여 의존성이 꼬이는 것을 막는 안전 옵션입니다.

  7. $ conda install numpy -n vision-ai --dry-run --json | head -5
{
  "actions": {
    "LINK": [...]

    의미: --json은 결과를 스크립트에서 파싱하기 좋은 형태로 바꿔줍니다. 자동화 도구가 conda 결과를 분석할 때 사용합니다.

  8. $ conda install pip
$ pip install some-package-not-on-conda
(conda로 pip 자체를 먼저 설치한 뒤, conda에 없는 패키지는 pip로 보완 설치)

    의미: conda에 없는 패키지는 pip로 보완하되, "conda 먼저, pip는 나중"이라는 순서 원칙을 지켜야 충돌을 줄일 수 있습니다.

  9. $ conda install numpy=1.26 --satisfied-skip-solve
(이미 조건을 만족하면 복잡한 재계산 없이 빠르게 스킵)

    의미: 이미 맞는 버전이 설치돼 있으면 복잡한 의존성 재계산(solve)을 건너뛰어 설치 속도를 크게 높입니다.

  10. $ conda install numpy --update-deps
(numpy뿐 아니라 관련된 의존 패키지들까지 함께 최신 상태로 갱신됨)

    의미: 기본은 의존성을 "필요한 만큼만" 건드리는데, --update-deps는 관련 패키지도 적극적으로 업데이트하도록 지시합니다.

3. conda list / env — 지금 환경 상태 확인하기

"지금 이 환경에 뭐가 깔려 있지?", "내가 환경을 몇 개나 만들었지?"에 답하는 명령들입니다. 문제가 생겼을 때 가장 먼저 확인하는 명령이기도 합니다.

conda list/env · 쉬움 10제

  1. $ conda list
# packages in environment at .../vision-ai:
#
numpy      1.26.4  py310...
pandas     2.2.0   py310...
...

conda list/env · 어려움 10제

  1. $ conda env export --no-builds > environment.yml
(빌드 해시 없이 "패키지명=버전"까지만 적힌 더 이식성 높은 yml 생성)

    의미: --no-builds는 OS나 CPU 아키텍처가 다른 컴퓨터에서도 재현이 잘 되도록 세부 빌드 정보를 뺍니다.

  2. $ conda env export --from-history > environment.yml
(내가 직접 설치 명령으로 넣은 패키지만 담긴 yml 생성)

    의미: --from-history는 "내가 실제로 요청한 패키지" 목록만 남겨 훨씬 깔끔하고 짧은 환경 파일을 만듭니다.

  3. $ diff <(conda list --export) <(conda list --export -n vision-ai-backup)
< numpy=1.26.4=py310...
> numpy=1.24.0=py310...

    의미: 두 환경의 패키지 export 결과를 diff로 비교하면 "무엇이 달라졌는지" 정확히 알 수 있습니다.

  4. $ conda list --revisions
rev 0: 최초 생성
rev 1: +numpy-1.26.4
rev 2: +pandas-2.2.0

    의미: conda는 환경이 바뀐 시점별 기록을 자동으로 남깁니다. 문제가 생긴 시점을 되짚어볼 때 유용합니다.

  5. $ conda install --revision 1
(환경이 1번 기록 시점 상태로 되돌아감 — 이후 설치한 패키지는 제거됨)

    의미: 특정 시점으로 환경을 되돌리는 명령입니다. "어제까지는 잘 됐는데" 상황의 해결책입니다.

  6. $ conda env list --json
{"envs": ["/home/kdt/anaconda3", "/home/kdt/anaconda3/envs/vision-ai"]}

    의미: 스크립트에서 "지금 만들어진 환경이 몇 개인지" 자동으로 세거나 검사할 때 활용합니다.

  7. $ conda list -e > requirements-conda.txt
(pip freeze와 비슷한 형태의 "이름=버전=빌드" 목록 파일 생성)

    의미: -e(export)로 파일에 바로 저장해두면 버전 관리(git)에 커밋해 팀과 공유할 수 있습니다.

  8. $ conda compare environment.yml
numpy found but mismatch. Have 1.26.4, need 1.24.0.

    의미: 현재 환경과 yml 파일 사이에 버전이 다른 패키지만 비교 출력합니다. 환경이 "문서와 실제 상태가 일치하는지" 자동으로 검증할 때 씁니다.

  9. $ conda list --show-channel-urls
numpy   1.26.4  py310...  https://repo.anaconda.com/pkgs/main
opencv  4.9.0   py310...  https://conda.anaconda.org/conda-forge

    의미: 각 패키지 뒤에 어느 채널에서 왔는지 표시합니다. 여러 채널을 섞어 쓴 환경에서 "이 패키지가 어디서 왔는지" 추적할 때 유용합니다.

  10. $ conda env config vars list -n vision-ai
(설정해 둔 환경변수 목록 출력, 없으면 빈 결과)

    의미: conda 환경별로 별도의 환경변수(예: CUDA_VISIBLE_DEVICES)를 저장해둘 수 있으며, 이를 조회하는 명령입니다.

4. pip — conda에 없는 패키지 설치하기

pip는 파이썬 자체의 표준 패키지 관리자입니다. conda로 큰 라이브러리(numpy, pytorch 등)를 깔고, conda에 없는 나머지는 pip로 보완하는 것이 이 과정의 원칙입니다.

pip · 쉬움 10제

  1. $ pip install requests
Collecting requests
Successfully installed requests-2.31.0

    의미: pip는 파이썬 패키지를 설치하는 기본 도구입니다. conda 환경 안에서 실행하면 그 환경에만 설치됩니다.

  2. $ pip install requests==2.31.0
(정확히 2.31.0 버전 설치)

    의미: ==버전으로 정확한 버전을 지정합니다.

  3. $ pip list
Package    Version
---------- -------
numpy      1.26.4
requests   2.31.0

    의미: conda list와 비슷하지만 pip 관점에서 본 패키지 목록입니다.

  4. $ pip show requests
Name: requests
Version: 2.31.0
Location: /home/kdt/anaconda3/envs/vision-ai/lib/python3.10/site-packages
Requires: charset-normalizer, idna, urllib3, certifi

    의미: 특정 패키지의 상세 정보(버전, 설치 위치, 의존성)를 확인합니다.

  5. $ pip install --upgrade requests
(이미 설치되어 있다면 최신 버전으로 업그레이드)

    의미: --upgrade(-U)는 오래된 버전을 최신으로 올립니다.

  6. $ pip uninstall requests
Proceed (y/n)? y
Successfully uninstalled requests-2.31.0

    의미: 설치된 패키지를 삭제합니다.

  7. $ pip freeze
numpy==1.26.4
pandas==2.2.0
requests==2.31.0

    의미: 지금 환경의 모든 패키지를 정확한 버전과 함께, 다른 곳에 그대로 설치 가능한 형식으로 보여줍니다.

  8. $ pip freeze > requirements.txt
(화면 출력 대신 requirements.txt 파일로 저장됨)

    의미: 리다이렉션(>)으로 freeze 결과를 파일로 저장하면 표준적인 "패키지 목록 파일"이 됩니다.

  9. $ pip install -r requirements.txt
(파일에 적힌 패키지들이 순서대로 전부 설치됨)

    의미: -r 파일명은 파일에 저장된 목록을 한 번에 설치합니다. 팀원의 환경을 그대로 재현할 때 표준적으로 씁니다.

  10. $ pip --version
pip 24.0 from /home/kdt/anaconda3/envs/vision-ai/lib/python3.10/site-packages/pip (python 3.10)

    의미: 지금 쓰이는 pip의 버전과 어느 파이썬에 연결된 pip인지 확인합니다(엉뚱한 환경의 pip를 쓰는 실수를 방지합니다).

pip · 어려움 10제

  1. $ pip install requests --no-cache-dir
(이전 캐시를 쓰지 않고 매번 새로 다운로드하여 설치)

    의미: 캐시가 손상되었거나 디스크 용량이 부족할 때 캐시를 아예 쓰지 않도록 강제합니다.

  2. $ pip install --index-url https://pypi.org/simple/ requests
(지정한 저장소에서만 패키지를 받아 설치)

    의미: 회사 내부에 자체 패키지 저장소(private PyPI)를 쓰는 경우 이 옵션으로 그 주소를 지정합니다.

  3. $ pip install "numpy>=1.20,<2.0"
(1.20 이상 2.0 미만 범위에서 적절한 버전 설치)

    의미: pip도 conda처럼 버전 범위 지정을 지원합니다.

  4. $ pip download numpy -d ./pkgs
(설치는 하지 않고 ./pkgs 폴더에 numpy 설치 파일(.whl)만 받아둠)

    의미: 인터넷이 안 되는 폐쇄망 서버에 옮겨 설치하기 위해 미리 파일만 받아둘 때 씁니다(원내 폐쇄망 데이터 보안 정책과 연결됩니다).

  5. $ pip install ./pkgs/numpy-1.26.4-cp310-cp310-linux_x86_64.whl
(인터넷 없이 로컬 파일만으로 설치 완료)

    의미: 위에서 미리 받아둔 .whl 파일을 폐쇄망 서버에서 오프라인으로 설치할 때 씁니다.

  6. $ pip list --outdated
Package  Version  Latest
-------  -------  ------
numpy    1.24.0   1.26.4

    의미: 지금 설치된 것 중 더 최신 버전이 있는 패키지 목록만 표시합니다. 업데이트가 필요한 패키지를 한 번에 파악할 때 씁니다.

  7. $ pip list --format=freeze | grep -iE "torch|numpy"
numpy==1.26.4
torch==2.2.0

    의미: 대량의 패키지 중 관심 있는 것만 grep과 조합해 빠르게 찾을 때 씁니다.

  8. $ pip install -e .
(현재 폴더의 코드를 "개발 모드"로 설치 — 코드 수정이 재설치 없이 바로 반영됨)

    의미: -e(editable)는 자신이 만든 패키지/모듈을 개발하면서 바로바로 테스트할 때 쓰는 표준 방식입니다.

  9. $ pip check
No broken requirements found.

    의미: 설치된 패키지들 사이에 버전 충돌이 있는지 자동으로 검사해줍니다. 충돌이 있으면 그 내역이 출력됩니다.

  10. $ pip install requests --target=./vendor
(기본 환경 경로가 아니라 지정한 ./vendor 폴더 안에 패키지가 설치됨)

    의미: --target은 패키지를 특정 폴더에 격리해서 담아둘 때 씁니다. Docker 이미지를 가볍게 만들거나 배포용 번들을 만들 때 활용되는 고급 옵션입니다.

5. activate · remove · clean — 핵심만 10개

변형이 많지 않은 명령들이라 쉬움/어려움을 나누지 않고, 꼭 필요한 10개를 표로 정리했습니다.

번호명령예상 결과의미
1conda activate base프롬프트가 (base)로 바뀜아무 환경도 지정 안 했을 때 기본으로 깔리는 conda 자체 환경으로 전환합니다
2conda deactivate (여러 번)겹겹이 activate했을 때 한 단계씩 벗어남activate를 여러 번 하면 스택처럼 쌓이며, deactivate도 그만큼 여러 번 눌러야 완전히 빠져나옵니다
3conda remove -n vision-ai opencvvision-ai 환경 안에서 opencv 패키지 하나만 삭제됨환경 전체가 아니라 패키지 하나만 지울 때 씁니다
4conda remove -n test-env --alltest-env 환경 전체가 삭제됨환경 자체를 통째로 없앨 때 씁니다
5conda clean --packages더 이상 어떤 환경에서도 쓰이지 않는 캐시된 패키지가 삭제됨디스크 공간을 확보할 때 씁니다
6conda clean --all -y캐시·임시파일·사용 안 하는 패키지가 확인 없이 전부 정리됨서버 청소 자동화 스크립트에서 자주 사용합니다
7conda config --set auto_activate_base false다음에 터미널을 열 때 base 환경이 자동으로 켜지지 않음매번 conda activate를 직접 치는 걸 선호할 때 설정합니다
8conda info --base/home/kdt/anaconda3 같은 설치 경로 출력conda 자체가 어디에 설치되어 있는지 확인할 때 씁니다
9which python (환경 활성화 후)/home/kdt/anaconda3/envs/vision-ai/bin/python 출력지금 활성화된 환경의 파이썬 실행 파일 경로를 최종 확인합니다
10conda --versionconda 24.x.x 형태 출력conda 자체의 버전을 확인합니다

한눈에 정리

명령어한 줄 정의가장 많이 쓰는 옵션실무에서 이럴 때 쓴다
conda create새로운 독립 작업 공간(환경)을 만든다-n python= -c -y --clone프로젝트마다 다른 파이썬·라이브러리 버전을 격리할 때
conda install지금 환경에 패키지를 추가한다-n -c --dry-run --no-depsnumpy, opencv, pytorch 등 핵심 라이브러리 설치
conda list/env지금 환경·패키지 상태를 확인한다env list --export env export환경을 남과 똑같이 재현하거나, 문제 시점을 되짚을 때
pipconda에 없는 패키지를 설치한다install freeze -r -econda에 없는 라이브러리 보완, requirements.txt 관리
activate/remove/clean환경을 전환·정리한다activate deactivate remove --all clean --all환경 전환, 안 쓰는 환경·캐시 정리로 디스크 확보
