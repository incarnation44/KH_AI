명령어 연습 부록 — if · for · ps · kill 각 20제 + 잡제어/cron

쉬운 예제 10개 → 어려운 예제 10개 순서로, 셸 스크립트와 프로세스 제어가 손에 익도록 반복 연습합니다

이 문서의 목표: D4에서 배운 조건문·반복문·프로세스 명령이 "낯선 문법"에서 "손에 익은 도구"가 되도록, 아주 쉬운 예제부터 실무에 가까운 예제까지 단계적으로 반복 연습합니다.

이 문서를 보는 법

  • 각 명령어마다 쉬움 10개 → 어려움 10개 순서로 배치되어 있습니다. 쉬움부터 순서대로 직접 타이핑해 보세요.
  • $로 시작하는 줄이 "내가 입력하는 명령"이고, 그 아래 줄이 예상 결과입니다. PID(프로세스 번호)는 실행할 때마다 달라지므로 예시 숫자와 다르게 나와도 정상입니다.
  • 각 예제 아래 의미가 "이 명령이 왜 이렇게 동작하는지"를 설명합니다.
  • 막히면 D4 본문(04.html)의 해당 절로 돌아가 개념을 다시 확인하세요.

실습 준비 — 예제 파일과 프로세스 만들기

mkdir -p ~/kdt-linux/cmd-practice-04 && cd ~/kdt-linux/cmd-practice-04

# fruits.txt — 반복문 연습용
cat > fruits.txt << 'EOF'
apple,5,1200
banana,10,800
cherry,3,5000
date,0,3000
elderberry,7,4500
EOF

# server.log — 조건문/ps 연습용
cat > server.log << 'EOF'
2026-08-20 09:20:11 ERROR Connection-timeout
2026-08-20 10:01:00 ERROR Out-of-memory
2026-08-20 11:00:00 WARNING Disk-usage-95%
EOF

# 빈 파일 하나 — 조건문 -s 테스트용
touch empty.txt

ls -l

예상 결과: fruits.txt, server.log, empty.txt 3개 파일이 만들어집니다. ps/kill 예제에서는 그때그때 sleep 300 & 같은 명령으로 연습용 프로세스를 직접 띄웁니다.

1. if — 조건에 따라 다르게 동작하기

if는 "조건이 참이면 이 코드를, 아니면 저 코드를 실행해줘"라고 지시하는 문법입니다. 스크립트가 상황에 따라 다르게 동작하게 만드는 가장 기본적인 도구입니다.

if · 쉬움 10제

  1. $ num=10
$ if [ $num -gt 5 ]; then echo "5보다 큽니다"; fi
5보다 큽니다

    의미: [ 조건 ]이 참이면 then과 fi 사이의 명령이 실행됩니다. -gt는 "~보다 크다(greater than)"는 뜻입니다.

  2. $ num=3
$ if [ $num -gt 5 ]; then echo "5보다 큽니다"; else echo "5 이하입니다"; fi
5 이하입니다

    의미: else는 조건이 거짓일 때 실행할 코드를 담습니다.

  3. $ name="kdt"
$ if [ "$name" = "kdt" ]; then echo "이름 일치"; fi
이름 일치

    의미: 문자열 비교는 숫자용 -eq가 아니라 =를 씁니다. 변수는 항상 큰따옴표로 감싸는 습관을 들이면 공백이 있어도 안전합니다.

  4. $ if [ -f fruits.txt ]; then echo "파일 있음"; else echo "파일 없음"; fi
파일 있음

    의미: -f는 "그 이름의 일반 파일이 존재하는가"를 검사합니다.

  5. $ if [ -d ~/kdt-linux ]; then echo "폴더 있음"; fi
폴더 있음

    의미: -d는 디렉토리(폴더) 존재 여부를 검사합니다.

  6. $ num=8
$ if [ $num -gt 5 ] && [ $num -lt 10 ]; then echo "5~10 사이"; fi
5~10 사이

    의미: &&는 앞뒤 두 조건이 모두 참일 때만 실행합니다.

  7. $ num=15
$ if [ $num -lt 5 ] || [ $num -gt 10 ]; then echo "범위 밖"; fi
범위 밖

    의미: ||는 둘 중 하나만 참이어도 실행합니다.

  8. $ score=75
$ if [ $score -ge 90 ]; then echo "A"
> elif [ $score -ge 80 ]; then echo "B"
> elif [ $score -ge 70 ]; then echo "C"
> else echo "F"; fi
C

    의미: elif로 여러 구간을 순서대로 검사하며, 처음으로 맞는 조건 하나에서 멈춥니다.

  9. $ if [ ! -f nofile.txt ]; then echo "파일이 없습니다"; fi
파일이 없습니다

    의미: !는 조건을 반대로 뒤집습니다. "없으면"을 표현할 때 자주 씁니다.

  10. $ name=""
$ if [ -z "$name" ]; then echo "값이 비어있음"; fi
값이 비어있음

    의미: -z는 문자열의 길이가 0인지(비어있는지) 검사합니다. 변수 입력을 제대로 받았는지 검증할 때 필수입니다.

if · 어려움 10제

  1. $ file="dataset_001.jpg"
$ if [[ $file == *.jpg ]]; then echo "이미지 파일"; fi
이미지 파일

    의미: [[ ]]는 bash 확장 조건식으로, *.jpg 같은 와일드카드 패턴 매칭을 지원합니다(기본 [ ]에서는 안 됩니다).

  2. $ log="ERROR: connection failed"
$ if [[ $log =~ ^ERROR ]]; then echo "에러 로그"; fi
에러 로그

    의미: =~는 정규식 매칭 연산자입니다. grep 없이도 셸 안에서 바로 패턴을 검사할 수 있습니다.

  3. $ if grep -q "ERROR" server.log; then echo "에러 있음"; else echo "에러 없음"; fi
에러 있음

    의미: if 뒤에는 [ ]뿐 아니라 아무 명령이나 올 수 있습니다. grep -q는 화면에 아무것도 출력하지 않고 "찾았는지 여부"만 종료코드로 돌려주므로 조건에 바로 쓰기 좋습니다.

  4. $ count=$(grep -c ERROR server.log)
$ if (( count > 0 )); then echo "에러 $count 건 발견"; fi
에러 2 건 발견

    의미: (( ))는 산술 비교 전용 문법으로, -gt 대신 사람이 읽기 쉬운 >, <, ==을 그대로 쓸 수 있습니다.

  5. $ ext="txt"
$ case $ext in
>   jpg|png) echo "이미지" ;;
>   txt|csv) echo "텍스트/데이터" ;;
>   *) echo "알 수 없음" ;;
> esac
텍스트/데이터

    의미: case는 값 하나를 여러 패턴과 비교할 때, if/elif를 여러 번 쓰는 것보다 훨씬 깔끔합니다.

  6. $ check_positive() { if [ $1 -gt 0 ]; then return 0; else return 1; fi; }
$ if check_positive -5; then echo "양수"; else echo "양수 아님"; fi
양수 아님

    의미: 함수도 종료코드(return)를 가지며, if는 그 종료코드로 참/거짓을 판단합니다(0=성공=참).

  7. $ if [ -x server.log ]; then echo "실행 가능"; else echo "실행 권한 없음"; fi
실행 권한 없음

    의미: -x는 "실행 권한이 있는가"를 검사합니다. 스크립트를 실행하기 전 안전장치로 자주 씁니다.

  8. $ for f in *.txt; do
>   if [ ! -s "$f" ]; then echo "$f 은 빈 파일"; fi
> done
empty.txt 은 빈 파일

    의미: -s는 "파일이 존재하고 크기가 0보다 큰가"를 검사합니다. !와 결합하면 "빈 파일 찾기"가 됩니다.

  9. $ if [ "$(whoami)" = "root" ]; then echo "관리자 계정"; else echo "일반 사용자"; fi
일반 사용자

    의미: $(명령)은 명령 실행 결과를 문자열로 바꿔주며, 그 값을 조건 비교에 바로 사용할 수 있습니다.

  10. $ cat > argcheck.sh << 'EOF'
#!/bin/bash
if [ $# -ne 2 ]; then
  echo "사용법: $0 입력파일 출력파일"
  exit 1
fi
echo "입력: $1, 출력: $2"
EOF
$ bash argcheck.sh a.txt
사용법: argcheck.sh 입력파일 출력파일

    의미: $#은 전달받은 인자의 개수입니다. 정확히 2개가 아니면 사용법을 안내하고 exit 1(실패)로 즉시 종료하는, 실무 스크립트의 필수 안전장치입니다.

2. for/while — 같은 작업을 반복하기

반복문은 "같은 작업을 목록의 개수만큼, 또는 조건이 참인 동안 계속" 실행하게 해줍니다. 파일 수백 개를 하나씩 처리할 때 반복문 없이는 사실상 불가능합니다.

반복문 · 쉬움 10제

  1. $ for i in 1 2 3; do echo "번호: $i"; done
번호: 1
번호: 2
번호: 3

    의미: for 변수 in 목록 형태로, 목록의 값을 하나씩 변수에 넣어가며 반복 실행합니다.

  2. $ for i in {1..5}; do echo "$i번째"; done
1번째
2번째
3번째
4번째
5번째

    의미: {시작..끝}은 그 사이의 숫자를 자동으로 나열해주는 문법입니다.

  3. $ for f in *.txt; do echo "파일: $f"; done
파일: argcheck.sh
파일: empty.txt
파일: fruits.txt
...(생략)...

    의미: *는 "모든"을 의미하는 와일드카드이며, for는 매칭된 파일 이름을 하나씩 변수에 담아 반복합니다.

  4. $ for i in $(seq 1 3); do echo "카운트 $i"; done
카운트 1
카운트 2
카운트 3

    의미: seq 시작 끝은 숫자 목록을 만들어주는 명령이고, $()로 그 결과를 for의 목록으로 사용합니다.

  5. $ for ((i=0; i<3; i++)); do echo "i=$i"; done
i=0
i=1
i=2

    의미: 다른 프로그래밍 언어와 비슷한 형태의 C스타일 for문도 bash에서 지원합니다.

  6. $ n=1
$ while [ $n -le 3 ]; do echo "n=$n"; n=$((n+1)); done
n=1
n=2
n=3

    의미: while은 조건이 참인 동안 계속 반복합니다. 안에서 변수를 직접 증가시켜야 무한루프를 피할 수 있습니다.

  7. $ for i in 1 2 3 4 5; do
>   if [ $i -eq 3 ]; then break; fi
>   echo $i
> done
1
2

    의미: break는 반복문을 즉시 빠져나갑니다. 3을 만나는 순간 멈춥니다.

  8. $ for i in 1 2 3 4 5; do
>   if [ $i -eq 3 ]; then continue; fi
>   echo $i
> done
1
2
4
5

    의미: continue는 그 순번만 건너뛰고 반복은 계속합니다. 3만 출력에서 빠집니다.

  9. $ fruits=(apple banana cherry)
$ for f in "${fruits[@]}"; do echo "$f"; done
apple
banana
cherry

    의미: 배열 ()로 여러 값을 묶어두고, "${배열[@]}"로 전체를 꺼내 반복할 수 있습니다.

  10. $ while read line; do echo "읽음: $line"; done < fruits.txt
읽음: apple,5,1200
읽음: banana,10,800
...(이하 동일)...

    의미: while read는 파일을 한 줄씩 읽어 변수에 담는 표준 패턴입니다. for보다 줄 단위 처리에 더 안전합니다.

반복문 · 어려움 10제

  1. $ for i in 1 2 3; do
>   for j in a b; do echo "$i$j"; done
> done
1a
1b
2a
2b
3a
3b

    의미: for 안에 for를 넣으면 "모든 조합"을 만들 수 있습니다. 여러 실험 설정(배치크기×러닝레이트) 조합을 만들 때 이 구조를 씁니다.

  2. $ IFS=',' read -ra cols <<< "apple,5,1200"
$ for c in "${cols[@]}"; do echo "필드: $c"; done
필드: apple
필드: 5
필드: 1200

    의미: IFS(구분자)를 콤마로 바꾸면 콤마 기준으로 나눠 배열에 담을 수 있습니다.

  3. $ for f in $(find . -name "*.txt"); do
>   echo "$f: $(wc -l < "$f")줄"
> done
./fruits.txt: 5줄
./server.log: 3줄
./empty.txt: 0줄

    의미: find의 결과를 for로 반복하며 각 파일마다 추가 작업(줄 수 세기)을 할 수 있습니다.

  4. $ for f in fruits.txt server.log missing.txt; do
>   if [ ! -f "$f" ]; then echo "$f 없음 — 건너뜀"; continue; fi
>   echo "$f 처리 중"
> done
fruits.txt 처리 중
server.log 처리 중
missing.txt 없음 — 건너뜀

    의미: continue와 조건문을 결합하면 "문제 있는 항목은 건너뛰고 나머지는 계속 처리"하는 견고한 배치 스크립트를 만들 수 있습니다.

  5. $ count=0
$ while true; do
>   count=$((count+1)); echo "체크 $count회"
>   if [ $count -ge 3 ]; then break; fi
>   sleep 1
> done
체크 1회
체크 2회
체크 3회

    의미: while true는 무한 반복이며, 안에 반드시 break 조건을 둬야 합니다. 서버 상태를 주기적으로 감시하는 스크립트의 기본 골격입니다.

  6. $ for i in 1 2 3; do (sleep 1; echo "작업 $i 완료") & done
$ wait
$ echo "전체 작업 종료"
작업 1 완료
작업 2 완료
작업 3 완료
전체 작업 종료

    의미: 반복문 안에서 &로 백그라운드 실행하면 여러 작업을 동시에 돌릴 수 있고, wait로 전부 끝날 때까지 기다립니다.

  7. $ fruits=(apple banana cherry)
$ for i in "${!fruits[@]}"; do echo "$i번째: ${fruits[$i]}"; done
0번째: apple
1번째: banana
2번째: cherry

    의미: !배열[@]는 "인덱스 목록"을 돌려줍니다. 값과 순서를 함께 다뤄야 할 때 씁니다.

  8. $ for f in *.txt; do
>   size=$(stat -c%s "$f")
>   if [ "$size" -eq 0 ]; then echo "삭제 대상(빈 파일): $f"; fi
> done
삭제 대상(빈 파일): empty.txt

    의미: stat -c%s로 파일 크기를 얻어 조건에 활용합니다. 데이터 정제 스크립트에서 불량 파일을 자동으로 찾아낼 때 쓰는 패턴입니다.

  9. $ files=(fruits.txt server.log empty.txt)
$ total=${#files[@]}
$ for i in "${!files[@]}"; do echo "[$((i+1))/$total] ${files[$i]} 처리 중"; done
[1/3] fruits.txt 처리 중
[2/3] server.log 처리 중
[3/3] empty.txt 처리 중

    의미: ${#배열[@]}는 배열의 전체 개수를 알려줍니다. 대량 파일 처리 시 "몇 번째/전체" 진행 상황을 보여주는 실무 패턴입니다.

  10. $ n=1
$ until [ $n -gt 3 ]; do echo "n=$n"; n=$((n+1)); done
n=1
n=2
n=3

    의미: until은 while과 반대로 "조건이 거짓인 동안" 반복합니다. "~가 될 때까지 기다린다"는 의미의 코드에서 while보다 자연스러운 경우가 있습니다.

3. ps — 지금 실행 중인 프로세스 보기

ps는 지금 컴퓨터 안에서 어떤 프로그램들이 실행되고 있는지 보여줍니다. 학습이 잘 돌고 있는지, 좀비처럼 남아있는 프로세스는 없는지 확인하는 눈 역할을 합니다.

ps · 쉬움 10제

  1. $ ps
  PID TTY          TIME CMD
 1234 pts/0    00:00:00 bash
 5678 pts/0    00:00:00 ps

    의미: 아무 옵션 없는 ps는 "지금 내 터미널에서 실행 중인" 프로세스만 간단히 보여줍니다.

  2. $ sleep 300 &
[1] 6001
$ ps
  PID TTY          TIME CMD
 1234 pts/0    00:00:00 bash
 6001 pts/0    00:00:00 sleep
 6010 pts/0    00:00:00 ps

    의미: &로 백그라운드 실행한 sleep도 ps 목록에 나타납니다. PID(6001)가 이 프로세스의 고유 번호입니다.

  3. $ ps aux | head -5
USER   PID %CPU %MEM COMMAND
kdt      1  0.0  0.1 systemd
kdt   1234  0.0  0.2 bash
kdt   6001  0.0  0.0 sleep
...

    의미: aux는 "모든 사용자(a)의, 터미널 없는 것까지 포함(x), 상세정보(u)"를 보여줍니다. 시스템 전체를 볼 때 가장 많이 쓰는 조합입니다.

  4. $ ps -ef | head -3
UID   PID  PPID  C STIME TTY      TIME CMD
root    1     0  0 09:00 ?    00:00:01 /sbin/init
kdt  1234  1200  0 09:05 pts/0 00:00:00 bash

    의미: -ef는 부모 프로세스 번호(PPID)까지 함께 보여줍니다. "누가 누구를 실행시켰는지" 파악할 때 씁니다.

  5. $ ps aux | grep sleep
kdt   6001  0.0  0.0  sleep 300
kdt   6020  0.0  0.0  grep sleep

    의미: ps를 grep과 함께 쓰면 "이름에 sleep이 들어간 프로세스만" 걸러볼 수 있습니다(검색 명령인 grep 자신도 함께 나오는 것이 특징입니다).

  6. $ pgrep sleep
6001

    의미: pgrep은 grep 없이도 이름으로 PID만 바로 찾아줍니다. ps | grep보다 스크립트에서 다루기 편합니다.

  7. $ ps -eo pid,cmd | grep sleep
 6001 sleep 300

    의미: -eo 컬럼1,컬럼2로 원하는 정보만 골라 출력할 수 있습니다.

  8. $ ps aux --sort=-%mem | head -3
USER   PID %CPU %MEM COMMAND
kdt   1234  0.5  2.1 python3
...

    의미: --sort=-%mem은 메모리 사용량이 큰 순서대로 정렬합니다(-는 내림차순).

  9. $ ps -ef --forest | head -5
UID   PID  PPID  CMD
kdt  1200     1  \_ bash
kdt  1234  1200      \_ vim

    의미: --forest는 부모-자식 관계를 들여쓰기로 보여줘 "무엇이 무엇을 실행시켰는지"를 한눈에 볼 수 있습니다.

  10. $ ps -u $(whoami) | wc -l
15

    의미: -u 사용자명은 특정 사용자의 프로세스만 보여주고, wc -l로 개수를 셀 수 있습니다.

ps · 어려움 10제

  1. $ ps -o pid,ppid,cmd -p 6001
 PID  PPID CMD
6001  1200 sleep 300

    의미: -p PID로 특정 프로세스 하나만 콕 집어 정보를 볼 수 있습니다. PPID로 "이 프로세스를 누가 실행했는지" 확인됩니다.

  2. $ ps -o pid,etime,cmd -p 6001
 PID     ELAPSED CMD
6001       02:15 sleep 300

    의미: etime은 프로세스가 시작된 후 얼마나 지났는지(경과 시간)를 보여줍니다. 오래 걸리는 학습이 몇 시간째 도는지 확인할 때 씁니다.

  3. $ ps -eLf | grep python | head -1
UID   PID   PPID   LWP  C NLWP STIME TTY TIME CMD
kdt  7001  1200  7001  0    4 09:00 pts/0 00:00:02 python3 train.py

    의미: -L은 프로세스 내부의 스레드(LWP)까지 각각 보여줍니다. 멀티스레드로 동작하는 학습 프로세스를 자세히 볼 때 씁니다.

  4. $ ps aux | awk '$8 ~ /D/ {print $2, $8, $11}'
7050 D python3

    의미: STAT 컬럼의 D는 "디스크 입출력 대기 중(멈춘 것처럼 보이지만 정상)"을 의미합니다. Z(좀비), D(디스크대기) 같은 상태코드는 트러블슈팅에 핵심 정보입니다.

  5. $ ps -u kdt -o pid,cmd | grep -E "python|sleep"
7001 python3 train.py
6001 sleep 300

    의미: 여러 조건(사용자+이름 패턴)을 조합해 "내가 띄운 학습/테스트 프로세스만" 골라볼 수 있습니다.

  6. $ ps -eo pid,%mem,rss,cmd --sort=-%mem | head -2 | awk '{printf "%s %.1fMB %s\n",$1,$3/1024,$4}'
7001 512.0MB python3

    의미: RSS는 KB 단위 실제 사용 메모리입니다. awk로 1024를 나눠 MB 단위로 변환해 사람이 읽기 편하게 만듭니다.

  7. $ watch -n 2 'ps aux --sort=-%cpu | head -5'
(2초마다 화면이 갱신되며 CPU 사용량 상위 5개 프로세스가 계속 보임)

    의미: watch 간격 '명령'은 지정한 간격(초)마다 명령을 반복 실행해 화면에 갱신합니다. top 대신 원하는 ps 조합을 실시간으로 볼 때 씁니다.

  8. $ ps -eo pid,args | grep train
7001 python3 train.py --epochs 100 --batch-size 32 --lr 0.001

    의미: args는 실행할 때 준 옵션까지 전체를 보여줍니다. "이 학습이 어떤 설정으로 돌고 있었는지" 뒤늦게 확인할 때 유용합니다.

  9. $ TARGET_PID=$(ps -eo pid,cmd | grep "python3 train.py" | grep -v grep | awk '{print $1}')
$ echo "학습 프로세스 PID: $TARGET_PID"
학습 프로세스 PID: 7001

    의미: ps+grep+awk 조합으로 원하는 프로세스의 PID만 뽑아 변수에 저장하면, 이후 kill이나 모니터링 스크립트에 바로 활용할 수 있습니다.

  10. $ lsof -p 7001 | grep -E "\.pt$|\.jpg$" | head -3
python3 7001 kdt   10r   REG    8,1  512000 model.pt

    의미: ps로 PID를 알아낸 뒤 lsof -p PID로 그 프로세스가 지금 열어서 쓰고 있는 파일 목록을 볼 수 있습니다. "학습이 어느 파일을 읽는 중에 멈췄는지" 진단할 때 유용합니다.

4. kill — 프로세스 종료하기

kill은 이름과 달리 항상 "죽이는" 것이 아니라, 프로세스에게 신호(signal)를 보내는 명령입니다. 대부분은 "정상적으로 종료해줘"라는 정중한 요청입니다.

kill · 쉬움 10제

  1. $ sleep 300 &
[1] 6001
$ kill 6001
$ jobs
[1]+  Terminated              sleep 300

    의미: kill PID는 그 프로세스에게 "종료해 달라"는 신호(기본 SIGTERM)를 보냅니다.

  2. $ kill 6001
$ ps -p 6001
    PID TTY          TIME CMD

    의미: kill 이후 ps -p PID로 다시 조회하면 결과가 없어(프로세스가 사라져) 정상 종료를 확인할 수 있습니다.

  3. $ sleep 300 & sleep 300 &
[1] 7001
[2] 7002
$ kill 7001 7002

    의미: kill 뒤에 PID를 여러 개 나열하면 한 번에 여러 프로세스를 종료할 수 있습니다.

  4. $ kill -9 7003

    의미: -9(SIGKILL)는 "정중히 요청"이 아니라 "무조건 즉시 강제 종료"입니다. 일반 kill로 안 꺼질 때 최후의 수단으로 씁니다.

  5. $ killall sleep

    의미: killall 이름은 PID를 몰라도 "이름이 sleep인 프로세스 전부"를 한 번에 종료합니다.

  6. $ pgrep sleep
7010
$ kill 7010

    의미: pgrep으로 PID를 먼저 알아낸 뒤 그 번호로 kill하는 조합은 스크립트에서 가장 안전하게 쓰는 방식입니다.

  7. $ pkill sleep

    의미: pkill은 killall과 비슷하게 이름으로 바로 종료합니다(pgrep의 kill 버전이라 생각하면 쉽습니다).

  8. $ kill -l | head -5
 1) SIGHUP  2) SIGINT  3) SIGQUIT  4) SIGILL  5) SIGTRAP

    의미: kill -l은 보낼 수 있는 모든 신호(signal) 종류 목록을 보여줍니다. 번호나 이름으로 지정할 수 있습니다.

  9. $ kill -SIGTERM 7020

    의미: -9처럼 번호 대신 -SIGTERM처럼 이름으로도 신호를 지정할 수 있습니다. 둘은 동일한 효과입니다.

  10. $ kill 99999
bash: kill: (99999) - No such process

    의미: 존재하지 않는 PID를 넣으면 에러 메시지가 뜹니다. kill 전에 ps나 pgrep으로 PID를 먼저 확인하는 습관이 중요한 이유입니다.

kill · 어려움 10제

  1. $ kill -SIGINT 7030

    의미: 터미널에서 Ctrl+C를 누르면 사실 이 SIGINT 신호가 전달되는 것입니다. 스크립트 안에서 "Ctrl+C를 흉내" 낼 때 씁니다.

  2. $ cat > graceful.sh << 'EOF'
#!/bin/bash
trap 'echo "종료 신호 받음, 정리 작업 수행 중..."; exit 0' SIGTERM SIGINT
while true; do sleep 1; done
EOF
$ bash graceful.sh &
$ kill $!
종료 신호 받음, 정리 작업 수행 중...

    의미: trap은 스크립트가 SIGTERM/SIGINT를 받았을 때 "그냥 죽지 말고 이 코드를 먼저 실행해라"고 지정합니다. 학습 중단 시 체크포인트를 저장하는 등 안전한 종료에 필수적입니다.

  3. $ kill -- -7040

    의미: PID 앞에 -를 붙이면 "그 프로세스가 속한 그룹 전체"를 종료합니다. 부모가 여러 자식을 만든 경우 하나만 죽이면 자식이 남을 수 있는데, 그룹킬로 한 번에 정리합니다.

  4. $ kill -SIGHUP 7050

    의미: 일부 서비스는 SIGHUP을 받으면 "설정을 다시 읽어 재시작"하도록 만들어져 있습니다. 서비스 재시작 없이 설정만 반영할 때 씁니다.

  5. $ for pid in $(pgrep -f "sleep 300"); do kill "$pid"; echo "$pid 종료함"; done
7060 종료함

    의미: pgrep -f로 명령줄 전체 기준 검색을 하고, for로 여러 개를 한 번에 종료합니다. 여러 실험 중 특정 설정만 골라 끄는 실무 패턴입니다.

  6. $ PID=7060
$ kill "$PID"; sleep 3
$ if ps -p "$PID" > /dev/null; then echo "정상 종료 실패, 강제 종료"; kill -9 "$PID"; fi

    의미: 먼저 정중하게 요청(kill)하고, 3초 기다려도 안 죽으면 그때 강제 종료(-9)합니다. 무작정 -9부터 쓰지 않는 것이 데이터 손상을 막는 안전한 습관입니다.

  7. $ kill 7070
$ if [ $? -eq 0 ]; then echo "종료 신호 전송 성공"; else echo "실패"; fi
종료 신호 전송 성공

    의미: $?는 바로 직전 명령의 종료코드입니다. kill이 신호 전송에 성공했는지 스크립트에서 자동으로 판단할 때 씁니다.

  8. $ pkill -f "python3 train.py"

    의미: -f 옵션은 프로세스 이름뿐 아니라 실행할 때 준 전체 명령줄까지 비교합니다. 같은 이름의 여러 스크립트 중 정확히 이 옵션 조합으로 실행된 것만 골라 종료할 때 유용합니다.

  9. $ pkill -u kdt -f "sleep"

    의미: -u 사용자명과 -f를 함께 쓰면 "이 사용자가 실행한, 이름에 sleep이 들어간 프로세스만" 종료합니다. 공용 서버에서 남의 프로세스를 실수로 건드리지 않도록 조건을 좁히는 방법입니다.

  10. $ timeout 5 sleep 300
$ echo $?
124

    의미: timeout 초 명령은 지정한 시간이 지나면 자동으로 kill(SIGTERM)을 보냅니다. 종료코드 124는 "시간 초과로 강제 종료됨"을 의미합니다 — 무한정 멈출 수 있는 작업에 안전장치를 걸 때 씁니다.

5. 잡 제어 · nohup · cron — 핵심만 12개

이 세 가지는 변형이 많지 않아 쉬움/어려움을 나누기보다, 꼭 필요한 12개를 표로 정리했습니다.

번호명령/키예상 결과의미
1Ctrl+Z (실행 중인 포그라운드 명령에서)[1]+ Stopped 명령어 표시 후 프롬프트로 복귀지금 실행 중인 작업을 잠시 멈추고(정지) 셸을 돌려받습니다
2jobs[1]+ Stopped sleep 300 처럼 현재 셸의 작업 목록 출력지금 떠 있는 백그라운드/정지된 작업들을 번호와 함께 확인합니다
3bg %1[1]+ sleep 300 & — 정지됐던 작업이 백그라운드에서 계속 실행됨Ctrl+Z로 멈춘 작업을 백그라운드에서 이어서 실행합니다
4fg %1해당 작업이 다시 포그라운드로 올라와 터미널을 점유함백그라운드 작업을 다시 눈앞으로 가져와 직접 제어할 때 씁니다
5python3 train.py &[1] 12345(PID 출력) 후 즉시 프롬프트 복귀처음부터 백그라운드로 실행을 시작합니다
6nohup python3 train.py &nohup: ignoring input and appending output to 'nohup.out'터미널을 닫아도(로그아웃해도) 프로세스가 계속 살아있게 합니다
7nohup python3 train.py > out.log 2>&1 &out.log 파일에 모든 출력이 저장됨nohup.out 대신 원하는 파일명으로 로그를 지정합니다
8crontab -e편집기가 열려 예약 작업 목록을 수정할 수 있음반복 실행할 작업(스케줄)을 등록·수정하는 명령입니다
9crontab -l0 3 * * * /home/kdt/backup.sh 처럼 등록된 목록 출력지금 등록되어 있는 cron 작업들을 확인합니다
10*/10 * * * * command (crontab 안에 작성)이후 10분마다 자동으로 command가 실행됨"분 시 일 월 요일" 5칸 형식으로 주기를 지정하며, */10은 "10 간격마다"라는 뜻입니다
11crontab -r등록된 모든 cron 작업이 삭제됨예약 작업 전체를 초기화합니다 (신중하게 사용해야 합니다)
120 9 * * 1-5 command평일(월~금) 오전 9시에만 실행되도록 등록됨요일 필드(1-5=월~금)로 "특정 요일에만" 실행되도록 제한합니다

한눈에 정리

명령/문법한 줄 정의가장 많이 쓰는 형태실무에서 이럴 때 쓴다
if조건에 따라 다른 코드를 실행한다[ ] [[ ]] (( )) grep -q파일 존재 확인 후 처리, 인자 개수 검증
for / while같은 작업을 반복한다for...in {1..n} while read수백 개 파일 일괄 처리, 여러 실험 조합 실행
ps지금 실행 중인 프로세스를 보여준다aux -ef --forest --sort학습이 잘 돌고 있는지, 메모리를 얼마나 쓰는지 확인
kill프로세스에게 신호를 보낸다kill -9 pkill -f trap멈춘 프로세스 종료, 안전한 학습 중단 처리
잡제어/nohup/cron작업을 백그라운드로 돌리고 예약한다Ctrl+Z bg fg nohup crontab -e로그아웃해도 학습이 계속 돌게, 매일 자동으로 검증 스크립트 실행
