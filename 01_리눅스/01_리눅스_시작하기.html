01

터미널이 뭔가요?

아이콘을 클릭하는 대신, 글자로 말을 거는 창입니다.

평소 컴퓨터를 쓸 때는 아이콘을 더블클릭하고, 마우스로 파일을 끌어다 옮기죠. 터미널은 이런 그림(아이콘) 없이, 글자만으로 컴퓨터에게 명령을 내리는 창입니다.

평소 쓰던 클릭 방식 vs 오늘 배울 타이핑 방식

터미널의 뼈대 — 셸과 커널

터미널 안에서는 사실 두 가지가 함께 일합니다.

셸 = 내 말을 알아듣는 통역사, 커널 = 실제로 몸을 움직이는 사람
  • 커널(Kernel) — 리누스 토르발스가 1991년 만든, 하드웨어(CPU·메모리·디스크)를 실제로 관리하는 핵심 프로그램. 우리가 직접 만질 일은 거의 없습니다.
  • 셸(Shell) — 우리가 타이핑한 명령을 해석해서 커널에 전달하는 프로그램. 오늘 우리가 대화하는 상대는 바로 이 셸(bash)입니다.
  • 배포판(Distribution) — 커널 + 여러 도구를 묶어 놓은 완제품. 우리는 Ubuntu(우분투)를 씁니다.
배포판어디서 쓰이나
Ubuntu (본 과정)여러분의 실습 PC, AWS 클라우드 학습 서버
Raspberry Pi OS교과 13 라즈베리파이 (Ubuntu와 사촌 관계)
JetPack (Ubuntu 기반)교과 14 NVIDIA Jetson 보드
💬 왜 굳이 이렇게 불편한 걸 배우나요?

이 과정 후반부의 결과물은 모니터도 마우스도 없는 장비(젯슨 보드, 라즈베리파이, 클라우드 서버) 위에서 돌아갑니다. 접속하면 딱 이 검은 화면 하나만 뜹니다. 터미널은 "선택 과목"이 아니라, 이후 모든 실습을 여는 유일한 열쇠입니다.

리눅스의 폴더 구조, 집이라고 생각하세요

폴더가 수백 개처럼 보여도, 매일 쓰는 곳은 서너 군데뿐입니다.

윈도우는 C드라이브, D드라이브처럼 여러 개로 나뉘어 있지만, 리눅스는 대문(/) 하나에서 모든 폴더가 갈라져 나갑니다.

집 하나(/) 안에 방(home)·창고(mnt)·공구함(bin, usr)이 있다고 생각하기

집안 곳곳, 방 이름표 전체 목록

아래는 실제 안내서에 나오는 전체 목록입니다. ★ 표시가 이 과정에서 실제로 자주 만질 곳입니다.

폴더비유실제 쓰임
/bin공구함ls, cp 같은 기본 명령어 실행파일
/etc ★안내문 게시판시스템 설정 파일(텍스트)
/home ★★★내 방사용자별 개인 폴더 (예: /home/kdt)
/root집주인 방root(관리자) 계정 전용 홈
/usr가전제품 창고설치된 응용 프로그램
/var ★우체통수시로 바뀌는 데이터, 로그(/var/log)
/tmp메모지임시 파일 (재부팅하면 사라짐)
/opt별채Anaconda 같은 대형 패키지가 자주 설치되는 곳
/mnt ★창고외부 저장소가 연결되는 지점 (대용량 데이터셋)
/media현관 신발장USB 등이 자동으로 연결되는 곳
/dev ★★콘센트·잭 구멍장치 파일. 카메라가 /dev/video0 로 나타남
/proc계기판커널·프로세스의 실시간 정보 (가상 파일시스템)
💬 실제로 이렇게 쓰입니다

/dev/video0은 교과 14 카메라, 교과 15 웹캠이 잡히는 자리이고, OpenCV의 cv2.VideoCapture(0)이 바로 이 파일을 엽니다. /mnt는 사진 수천 장을 홈이 아니라 별도 디스크에 보관하는 현업 표준 위치입니다. /var/log는 나중에 학습이 죽었을 때 원인을 찾는 곳입니다.

윈도우와 다른 점 3가지

WindowsLinux
최상위C:\, D:\ 로 분리/ 하나 (모든 것이 여기서 시작)
경로 구분자\ (역슬래시)/ (슬래시)
대소문자구분 안 함 (Data = data)구분함 (Data ≠ data)
💡 실제 사고 사례 훈련생이 Images/ 폴더를 만들고 코드에서는 images/를 참조 → Windows에서는 동작하지만 Jetson에 올리면 FileNotFoundError가 납니다. 교과 14 배포 단계에서 자주 나오는 실수이니 대소문자를 항상 정확히 맞추는 습관을 들이세요.

주소(경로) 읽는 법

"정확한 도로명 주소"와 "여기서 두 블록" 두 가지 방식
표기뜻비유
/home/kdt/photo.jpg대문(/)부터 시작하는 정확한 주소도로명 주소

터미널
여러 예시로 감 잡기

# make_sample_dataset.sh
# 교과 8/14 실데이터와 동일한 구조의 더미 데이터셋 생성
set -e

ROOT=~/kdt-linux/dataset/kimchi
N=1000

mkdir -p "$ROOT/raw"
cd "$ROOT/raw"

echo "[1/3] 이미지 $N 장 생성 중..."
for i in $(seq -w 1 $N); do
    printf '\xff\xd8\xff\xe0dummy-jpeg-%s' "$i" > "kimchi_${i}.jpg"
done

echo "[2/3] 라벨 TXT 생성 중..."
for i in $(seq -w 1 $N); do
    CLS=$(( RANDOM % 6 ))
    X=$(awk -v s=$RANDOM 'BEGIN{srand(s);printf "%.6f", rand()}')
    Y=$(awk -v s=$RANDOM 'BEGIN{srand(s);printf "%.6f", rand()}')
    W=$(awk -v s=$RANDOM 'BEGIN{srand(s);printf "%.6f", rand()*0.3+0.05}')
    H=$(awk -v s=$RANDOM 'BEGIN{srand(s);printf "%.6f", rand()*0.3+0.05}')
    echo "$CLS $X $Y $W $H" > "kimchi_${i}.txt"
done

echo "[3/3] 의도적 오류 데이터 주입 (검증 실습용)..."
rm -f kimchi_0007.txt
rm -f kimchi_0123.jpg
echo "9 1.500000 0.400000 0.200000 0.200000" > kimchi_0456.txt
> kimchi_0789.txt
touch "kimchi 0999.jpg"

echo "완료: $(ls *.jpg | wc -l) 이미지 / $(ls *.txt | wc -l) 라벨"

실습 · 와일드카드와 find로 파일 찾기

Step 1. 와일드카드(글로빙) — 이름 패턴으로 찾기

*
0글자 이상, 아무 문자나 다 해당
?
정확히 한 글자
[1-3]
범위 중 한 글자 (1,2,3 중 하나)

$ ls kimchi_000?.jpg        # kimchi_000 뒤에 딱 한 글자만
$ ls kimchi_00[1-3]0.jpg    # 1,2,3 중 하나가 그 자리에
$ ls *.{jpg,txt} | head     # jpg 또는 txt 확장자

Step 2. find — 조건으로 찾기

터미널
find 다섯 가지 예제
$ find . -name "*.jpg" | wc -l         # 확장자로 찾아서 개수 세기
$ find . -name "kimchi_01??.jpg" | head # 이름 패턴
$ find . -name "*.txt" -size 0          # 크기 0인 빈 파일 찾기

$ find . -name "* *"                     # 이름에 공백이 있는 파일 찾기 ★ 실무 빈출 사고

Step 3. 실무 미션 — 정합성 1차 점검 핵심

미션 A. 라벨이 없는 이미지 찾기

터미널
이미지-라벨 짝 맞추기
$ ls *.jpg | sed 's/\.jpg$//' | sort > /tmp/imgs.txt
$ ls *.txt | sed 's/\.txt$//' | sort > /tmp/lbls.txt
$ comm -23 /tmp/imgs.txt /tmp/lbls.txt   # 이미지엔 있는데 라벨엔 없는 것 (차집합)
kimchi_0123
$ comm -13 /tmp/imgs.txt /tmp/lbls.txt   # 반대: 라벨엔 있는데 이미지엔 없는 것
kimchi_0007
sed 's/\.jpg$//' 는 파일 이름 끝의 ".jpg"를 지워서 이름만 남기는 명령입니다. comm은 정렬된 두 목록을 비교해서 "한쪽에만 있는 것"을 찾아줍니다.
💬 왜 이게 중요한가

YOLO 학습 시 라벨 없는 이미지는 "객체가 하나도 없는 배경 이미지"로 학습됩니다. 의도치 않은 배경 학습은 교과 8·14에서 mAP를 떨어뜨리는 대표 원인입니다. 목표 성능이 mAP@0.5 ≥ 0.7이므로 이 점검은 필수 절차입니다.

미션 B. 공백 파일명 정리

터미널
공백 파일명 고치기
$ mv "kimchi 0999.jpg" "kimchi_0999.jpg"
$ find . -name "* *"        # 이제 아무것도 안 나와야 정상
★ 심화 미션 (전공자용, 선택) — 여러 개를 한 번에 바꾸기

공백 파일명이 여러 개일 때, 하나씩 고치지 않고 한 번에 바꾸는 방법입니다.

터미널
한 번에 바꾸기
$ find . -name "* *" -type f | while read -r f; do
    mv "$f" "$(echo "$f" | tr ' ' '_')"
done

실습 · 복사·이동·삭제, 그리고 원격 접속

내 컴퓨터 안에서의 이동뿐 아니라, 다른 컴퓨터로도 옮겨봅니다.

Step 1. cp / mv / rm 세 형제

터미널
복사 · 이동 · 삭제 연습
$ cp kimchi_0001.jpg ../images/train/    # 한 개 복사
$ ls ../images/train/
kimchi_0001.jpg

$ mkdir -p /tmp/backup_test

$ ls -R /tmp/backup_test

$ touch /tmp/old.txt
$ mv /tmp/old.txt /tmp/new.txt           # 이동(이름 변경도 mv)

$ rm -i /tmp/new.txt                     # 확인 옵션 -i 습관화
$ rm -rf /tmp/backup_test
cp 옵션뜻
-r디렉토리 재귀 복사
-p타임스탬프·권한 보존
-v진행 상황 출력
-n기존 파일 덮어쓰지 않음
-a-rp + 링크 보존 (아카이브)

Step 2. 데이터셋 원본 보호 ⚠️

터미널
원본 쓰기 잠그기
$ chmod -R a-w raw          # raw 폴더 전체 쓰기 금지
$ touch raw/test.txt        # → Permission denied 확인
$ chmod -R u+w raw          # 필요할 때만 다시 해제
⭐ 현업 규칙 raw/는 절대 손대지 않습니다. 모든 전처리는 복사본에서 합니다. 원본을 덮어쓴 순간 그 데이터셋은 재현 불가능해지고, 평가항목 「데이터 품질」에서 감점됩니다.

Step 3. 원격 접속 (SSH)

SSH는 다른 컴퓨터에 전화를 걸어, 그 컴퓨터의 터미널을 그대로 내 화면에 띄우는 것이라고 생각하면 됩니다. AWS 학습 서버, 젯슨 보드에 접속할 때 항상 이 방법을 씁니다.

터미널
SSH 접속 연습
$ ssh -V                     # SSH 클라이언트가 설치돼 있는지 확인
$ ssh 사용자명@서버주소        # 예: ssh kdt@192.168.0.10
kdt@server:~$ hostname     # 접속 후, 지금 어느 장비에 있는지 꼭 확인
kdt@server:~$ pwd
kdt@server:~$ exit         # 또는 Ctrl+D 로 나가기

Windows에서 MobaXterm을 쓴다면

  1. Session → SSH 선택
  2. Remote host에 강사 안내 IP 입력
  3. Specify username 체크 후 계정 입력
  4. OK → 비밀번호 입력
  5. 좌측 SFTP 패널에서 드래그로 파일 전송 가능

Step 4. 파일 전송 — scp / rsync

터미널
scp 로 옮기기
$ scp meta/classes.txt kdt@서버주소:~/         # 로컬 → 원격
$ scp kdt@서버주소:~/classes.txt /tmp/          # 원격 → 로컬
$ scp -r meta kdt@서버주소:~/                   # 폴더 전송
터미널
rsync 로 변경분만 전송 ★
$ rsync -avh --progress images/ kdt@서버주소:~/images/
rsync 옵션뜻
-a아카이브(권한·시간 보존, 재귀)
-v상세 출력
-h사람이 읽기 좋은 크기 단위
--progress진행률 표시
--dry-run실제로 전송 안 하고 미리보기 (항상 먼저 실행)
💬 왜 rsync인가

이미지 1,000장을 학습 서버에 올렸는데 나중에 50장만 수정했다면, scp는 1,000장을 처음부터 다시 보내지만 rsync는 바뀐 50장만 보냅니다. 클라우드 학습에서 시간과 비용이 직접 차이납니다.

⚠️ 보안 주의 ㈜비솔 제공 실데이터는 원내 폐쇄망 전용입니다. 외부 클라우드로의 rsync/scp 전송은 금지되며, 개인별 보안서약서 대상입니다. 오늘 실습은 더미 데이터로만 진행합니다.
