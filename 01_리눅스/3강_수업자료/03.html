PART 1. 이론 (3H)

1교시 · 왜 CLI 편집기인가 · Nano (50분)

1.1 이 화면을 반드시 만나게 됩니다

kdt@raspberrypi:~ $ nano /boot/firmware/config.txt

교과 13(Raspberry Pi), 교과 14(Jetson Orin Nano Super)에서 여러분이 보게 될 화면입니다. GUI가 없고, VS Code도 없고, 마우스도 없습니다. CLI 편집기 외에 파일을 고칠 방법이 없습니다.

상황 필요한 편집
Jetson에서 CUDA 경로 설정 ~/.bashrc 수정
Raspberry Pi 카메라 활성화 /boot/firmware/config.txt 수정
학습 서버 하이퍼파라미터 급수정 config.yaml 수정
SSH 접속 설정 변경 /etc/ssh/sshd_config 수정
크론 스케줄 등록 crontab -e (기본 편집기 실행)

1.2 Nano — 5분이면 배우는 편집기

nano 파일명

화면 하단에 단축키가 표시됩니다. ^ 는 Ctrl 입니다.

키 기능
Ctrl+O 저장 (Write Out) → Enter로 파일명 확정
Ctrl+X 종료 (eXit)
Ctrl+K 한 줄 잘라내기
Ctrl+U 붙여넣기
Ctrl+W 검색 (Where is)
Ctrl+\ 치환
Ctrl+G 도움말
Alt+U 실행 취소

Nano를 쓰는 상황: 한두 줄만 급하게 고칠 때. 빠르고 실수가 없습니다.

1.3 Vim — 왜 굳이 배우는가

이유 설명
어디에나 있다 최소 설치 리눅스, Docker 컨테이너, 임베디드 보드에 기본 탑재
git commit 기본 편집기 설정 안 하면 vim이 뜹니다 (6일차)
키보드만으로 빠름 손이 홈 포지션을 벗어나지 않음
원격 편집에 최적 마우스·GUI 불필요

목표는 "Vim 마스터"가 아닙니다. "vim이 떴을 때 당황하지 않고 저장·종료·검색·치환을 할 수 있다" 가 목표입니다.

2교시 · Vim 핵심 (50분)

2.1 모드 개념 — Vim의 전부

        ┌──────────────┐
   i,a,o│              │Esc
   ┌───▶│  입력 모드     │────┐
   │    │  (Insert)     │    │
   │    └──────────────┘    ▼
┌──┴────────────┐      ┌─────────────┐
│  명령 모드      │◀─────│  명령 모드    │
│  (Normal)     │      │  (Normal)   │
└──┬────────────┘      └─────────────┘
   │ :                        ▲
   ▼                          │ Esc/Enter
┌──────────────┐              │
│  실행 모드      │──────────────┘
│  (Command)   │
└──────────────┘

"길을 잃으면 Esc를 두 번 누른다" — 이것만 기억하면 Vim에서 절대 갇히지 않습니다.

2.2 최소 생존 명령

목적 키
입력 시작 i (커서 앞), a (커서 뒤), o (아래 새 줄)
명령 모드 복귀 Esc
저장 :w
저장 후 종료 :wq 또는 ZZ
저장 없이 강제 종료 :q!

2.3 이동

키 이동
h j k l 좌 하 상 우
w / b 다음/이전 단어
0 / $ 줄 처음/끝
gg / G 문서 처음/끝
:42 42번 줄로
Ctrl+d / Ctrl+u 반 페이지 아래/위

2.4 편집

키 기능
x 한 글자 삭제
dd 한 줄 삭제(잘라내기)
5dd 5줄 삭제
yy 한 줄 복사
p / P 아래/위에 붙여넣기
u 실행 취소
Ctrl+r 다시 실행
. 직전 명령 반복 ★

2.5 검색·치환 (실무 최다 사용)

/foreign            " 아래로 검색 (n 다음, N 이전)
?foreign            " 위로 검색

:%s/old/new/g       " 전체 파일 치환 ★
:%s/old/new/gc      " 치환할 때마다 확인
:10,20s/old/new/g   " 10~20줄만

2.6 실용 설정

명령 효과
:set nu 줄 번호 표시
:set hlsearch 검색 결과 하이라이트
:noh 하이라이트 끄기
:syntax on 문법 강조
:set paste 붙여넣기 시 자동 들여쓰기 방지 ★

:set paste 를 모르면 원격 서버에 파이썬 코드를 붙여넣을 때 들여쓰기가 계단식으로 망가집니다. 교과 13·14에서 반드시 겪는 문제입니다.

3교시 · 정규표현식과 텍스트 처리 3종 (50분)

3.1 정규표현식 최소 문법

패턴 의미 예시
. 아무 문자 1개 a.c → abc, axc
* 앞 문자 0회 이상 ab* → a, ab, abb
+ 앞 문자 1회 이상 ab+ → ab, abb
? 앞 문자 0~1회 ab? → a, ab
^ 줄 시작 ^ERROR
$ 줄 끝 \.jpg$
[] 문자 집합 [0-9], [a-z]
[^] 부정 [^0-9]
\d \w \s 숫자·단어문자·공백 (grep -P)
{n,m} n~m회 반복 [0-9]{4}
\| OR (기본 grep) error\|fail
() 그룹 (ab)+

3.2 3종 도구의 역할 분담

도구 한 문장 대표 용도
grep "찾는다" 로그에서 ERROR 줄 찾기
sed "고친다" 라벨 클래스 ID 일괄 변경
awk "계산한다" 컬럼 단위 통계·포맷 변환

3.3 grep

grep "패턴" 파일
grep -i    # 대소문자 무시
grep -n    # 줄 번호 표시
grep -r    # 디렉토리 재귀
grep -v    # 반대(패턴이 없는 줄)
grep -c    # 개수만
grep -l    # 파일명만
grep -E    # 확장 정규식 (egrep)
grep -A3 -B3   # 앞뒤 3줄 함께

3.4 sed

sed 's/찾을것/바꿀것/'      # 각 줄 첫 번째만
sed 's/찾을것/바꿀것/g'     # 전부
sed -i 's/a/b/g' 파일       # 파일 직접 수정 ★위험
sed -i.bak 's/a/b/g' 파일   # 백업 남기고 수정 (권장)
sed -n '5,10p' 파일         # 5~10줄만 출력
sed '/패턴/d' 파일           # 패턴 포함 줄 삭제

⚠️ sed -i 는 되돌릴 수 없습니다. 항상 -i.bak 또는 -i 없이 먼저 결과를 확인하십시오.

3.5 awk

awk '{print $1}'                   # 1번째 필드
awk -F',' '{print $2}'             # 구분자 콤마
awk '$1==3 {print}'                # 조건
awk '{sum+=$4} END {print sum}'     # 누적 합
awk 'NR==1 {print}'                 # 첫 줄
awk '{printf "%-10s %5.2f\n", $1, $4}'   # 서식 출력
내장 변수 의미
$0 줄 전체
$1 $2 ... n번째 필드
NF 필드 개수
NR 전체 줄 번호
FNR 현재 파일 내 줄 번호
FILENAME 파일명

Step 2. 기본 검색 미션

# M1. ERROR 줄만
grep "ERROR" train.log

# M2. ERROR 개수
grep -c "ERROR" train.log

# M3. WARN 또는 ERROR (줄 번호와 함께)
grep -nE "WARN|ERROR" train.log

# M4. INFO 가 아닌 줄
grep -v "INFO" train.log

# M5. ERROR 발생 전후 2줄까지 (원인 파악)
grep -B2 -A2 "CUDA out of memory" train.log

# M6. mAP50 값이 기록된 줄만
grep -o "mAP50=[0-9.]*" train.log

# M7. 목표 성능 0.7 이상 달성 시점 찾기 ★
grep -oE "mAP50=0\.[7-9][0-9]*" train.log

M7의 의미: 안내서 교과 14 목표 성능은 mAP@0.5 기준 0.7 이상입니다. 학습 로그에서 목표 달성 시점을 찾는 것이 실제 프로젝트 절차입니다.

Step 3. 라벨 파일 검색 미션

cd ~/kdt-linux/dataset/kimchi/raw

# M8. 클래스 0(leaf)이 포함된 라벨 파일 목록
grep -l "^0 " *.txt | head

# M9. 클래스 0 포함 파일 개수
grep -l "^0 " *.txt | wc -l

# M10. 좌표에 1보다 큰 정수부가 있는 라벨 찾기 (범위 초과)
grep -E "( [1-9][0-9]*\.)" *.txt

# M11. 클래스 ID가 6 이상인 잘못된 라벨
grep -E "^[6-9] " *.txt

실습 3-4 · sed로 라벨 일괄 변환 (60분) ★핵심


배경 (실무 상황)


교과 8 데이터는 이물 6종이지만, 그중 4번 고무장갑은 "사용하지 않음" 으로 안내서에 명시되어 있습니다. 또한 교과 14 프로젝트는 클래스 5종 이상이면 됩니다.
→ 클래스 재매핑(remapping)이 필요합니다. 이건 현업에서 매우 흔한 작업입니다.


Step 1. 안전한 작업 준비

Step 2. sed 미리보기 (파일 수정 전)


# 클래스 3(rubber_glove) 을 사용하지 않으므로 제거 대상 확인
grep -l "^3 " *.txt | wc -l

# 변환 규칙 설계
# 기존: 0 leaf / 1 plastic / 2 branch / 3 glove(제거) / 4 disease / 5 pepper
# 신규: 0 leaf / 1 plastic / 2 branch / 3 disease / 4 pepper

# 먼저 화면으로 결과 확인 (파일 수정 안 함)
sed 's/^4 /3 /' kimchi_0001.txt
sed 's/^5 /4 /' kimchi_0002.txt



Step 3. 순서 함정 이해하기 ★


# 잘못된 방법 — 순차 적용 시 중복 변환 발생
echo "4 0.5 0.5 0.1 0.1" | sed 's/^4 /3 /' | sed 's/^3 /2 /'
# → 2 ... : 4가 3을 거쳐 2가 되어버림

# 올바른 방법 ① — 임시 마커 사용
echo "4 0.5 0.5 0.1 0.1" | sed -e 's/^4 /X3 /' -e 's/^5 /X4 /' -e 's/^X//'

# 올바른 방법 ② — sed 의 다중 표현식은 줄 단위로 순차 적용되므로
#   높은 번호부터 처리해도 안전하지 않음. 마커 방식이 안전합니다.





여기서 배울 것: 일괄 치환은 항상 "겹침(collision)"을 의심해야 합니다. 라벨 재매핑 실수는 학습을 끝까지 돌린 뒤에야 성능 이상으로 드러나서, 며칠을 날립니다.




Step 4. 실제 변환 수행


cd ~/kdt-linux/dataset/kimchi/work

# 1) 클래스 3(glove) 라벨 줄 삭제

# 2) 재매핑 (마커 방식)
sed -i -e 's/^4 /X3 /' -e 's/^5 /X4 /' -e 's/^X//' *.txt

# 3) 검증
cat *.txt | cut -d' ' -f1 | sort | uniq -c
# 0,1,2,3,4 만 있어야 정상

# 4) 빈 파일이 생겼는지 확인 (모든 객체가 glove였던 이미지)
find . -name "*.txt" -size 0 ! -name "*.bak" | wc -l

# 5) 백업 파일 정리
mkdir -p .sedbak && mv *.bak .sedbak/



Step 5. 추가 sed 미션


# M1. 소수점 6자리를 4자리로 줄이기 (파일 용량 절감)

# M2. 구분자를 공백 → 콤마로 (CSV 변환)

# M3. 모든 줄 앞에 파일명 주석 추가
sed "1i # source: kimchi_0001.txt" kimchi_0001.txt | head -3

클래스 재매핑 외에도 sed는 "형식을 통째로 갈아엎어야 하는" 실무 상황에서 자주 쓰입니다. 아래 6개는 실제 데이터 파이프라인에서 반복적으로 마주치는 정제 작업입니다.

# M5. [목적] 수백 개 라벨 파일의 경로 표기를 새 서버 구조에 맞게 한 번에 바꾼다

#        노출되면 안 됩니다. sed로 "패턴에 해당하는 부분만" 마스킹 처리합니다.
echo "/home/kdt2026/dataset/kimchi/raw/kimchi_0001.jpg 로드 완료" | \

# M7. [목적] 여러 종류의 공백(탭·다중 스페이스)이 섞인 지저분한 라벨 파일을 표준 포맷으로 통일한다
# [설명] 사람이 손으로 만든 라벨이나, 서로 다른 라벨링 툴에서 export한 파일은
#        공백 개수가 제각각인 경우가 많습니다. 정규식 \s+ 로 한 번에 단일 공백으로 통일합니다.
printf 'class1   0.512  0.334   0.1  0.2\n' | sed -E 's/[ \t]+/ /g'

# [설명] sed -n 'p'는 조건에 맞는 줄만 출력용으로 뽑을 때 grep 대신 자주 쓰입니다.

echo "LEAF_TYPE 0.5 0.5 0.1 0.1" | \
  sed -e 's/^LEAF_TYPE/leaf/' -e 's/^Leaf/leaf/' -e 's/^LEAF/leaf/'

echo "kimchi_0001,leaf,0.51,0.33" | sed -E 's/^([^,]+),([^,]+),(.*)$/\2,\1,\3/'

실습 3-5 · awk로 통계와 포맷 변환 (60분) ★핵심


Step 1. 필드 다루기 기초


cd ~/kdt-linux/dataset/kimchi/work

cat kimchi_0001.txt
awk '{print $1}' kimchi_0001.txt              # 클래스
awk '{print $4, $5}' kimchi_0001.txt          # width height
awk '{print NF}' kimchi_0001.txt              # 필드 개수 (5여야 정상)
awk '{print FILENAME, NR, $0}' kimchi_0001.txt



Step 2. 검증 미션


# M1. 필드가 5개가 아닌 잘못된 라벨 찾기 ★
awk 'NF!=5 && NF!=0 {print FILENAME": NF="NF" -> "$0}' *.txt

# M2. 좌표 범위(0~1) 위반 검출
awk '{for(i=2;i<=5;i++) if($i<0||$i>1){print FILENAME": "$0; next}}' *.txt

# M3. bbox가 이미지 밖으로 나가는 경우 (중심±절반이 범위 초과)
awk '{
  if ($2-$4/2 < 0 || $2+$4/2 > 1 || $3-$5/2 < 0 || $3+$5/2 > 1)
    print FILENAME": out of bounds -> "$0
}' *.txt | head



Step 3. 통계 미션


# M4. 클래스별 개수 (awk 단독)
awk '{cnt[$1]++} END {for (c in cnt) print c, cnt[c]}' *.txt | sort -n

# M5. 클래스별 평균 bbox 면적 ★
awk '{area[$1]+=$4*$5; n[$1]++}
     END {for (c in area) printf "class %s: avg_area=%.5f (n=%d)\n", c, area[c]/n[c], n[c]}' *.txt | sort

# M6. 전체 bbox 면적 통계 (최소/최대/평균)
awk '{a=$4*$5; s+=a; if(min==""||a<min)min=a; if(a>max)max=a; n++}
     END {printf "min=%.5f max=%.5f avg=%.5f n=%d\n", min, max, s/n, n}' *.txt

# M7. 이미지당 객체 수 분포
awk 'END {}{c[FILENAME]++} END {for(f in c) print c[f]}' *.txt | sort -n | uniq -c



Step 4. 포맷 변환 미션 ★실무 직결


교과 7에서 만들 라벨링 툴은 XML/JSON을 다루고, 교과 8·14는 YOLO TXT를 씁니다. 포맷 변환은 반드시 필요합니다.


cd ~/kdt-linux/dataset/kimchi/work

# M8. YOLO(정규화) → 픽셀 좌표 변환 (이미지 4848x2704 가정)
awk -v W=4848 -v H=2704 '{
  x1 = ($2 - $4/2) * W;  y1 = ($3 - $5/2) * H;
  x2 = ($2 + $4/2) * W;  y2 = ($3 + $5/2) * H;
  printf "%d %.0f %.0f %.0f %.0f\n", $1, x1, y1, x2, y2
}' kimchi_0001.txt

# M9. 전체를 하나의 CSV로 통합 ★
{
  echo "filename,class,x_center,y_center,width,height"
  awk '{ split(FILENAME, a, "."); print a[1]","$1","$2","$3","$4","$5 }' *.txt
} > ~/kdt-linux/dataset/kimchi/meta/annotations.csv

head -5 ~/kdt-linux/dataset/kimchi/meta/annotations.csv

Step 4.5 실무 확장 미션 — 학습 로그 통계 리포트 6종 ★취업 현장 빈출


awk는 "숫자가 섞인 텍스트를 계산기처럼 다루는" 도구입니다. 라벨 좌표뿐 아니라, 학습 로그에서 성능 지표를 뽑아 리포트를 만드는 작업이 실무에서 awk가 가장 많이 쓰이는 순간입니다.


cd ~/kdt-linux/logs

# M10. [목적] epoch가 진행되며 loss가 실제로 감소하는 추세인지 한눈에 확인한다
# [설명] awk에서 정규식으로 원하는 줄만 골라(/패턴/) 필요한 필드만 뽑으면
#        엑셀에 붙여넣기 좋은 형태의 "epoch, loss" 2열 표가 만들어집니다.
awk -F'[= ]' '/Epoch/{print $5, $8}' train.log
# 필드 구분자를 '=' 와 공백 두 가지로 지정해 "loss=1.2345"에서 숫자만 정확히 분리합니다.

# M11. [목적] 목표 성능(mAP50 0.7)을 처음 넘긴 epoch를 자동으로 찾아 보고서에 쓴다
# [설명] awk 조건문(if)과 정규식을 함께 쓰면 "특정 조건을 처음 만족하는 지점"을
#        찾고 나서 즉시 종료(exit)할 수 있어 대용량 로그에서도 빠릅니다.
awk -F'[= ]' '/mAP50/{ep=$5; map=$NF} map+0>=0.7{print "목표 달성: epoch", ep, "mAP50="map; exit}' train.log

# M12. [목적] GPU 메모리 경고가 몇 번, 어느 시점에 발생했는지 빈도와 시간을 함께 뽑는다
# [설명] 여러 필드를 조합해 "시간 + 경고 종류"를 함께 출력하면, 장애 재현·리포트 작성 시
#        "언제 반복적으로 발생하는가"를 바로 보여줄 수 있습니다.
awk '/GPU memory/{count++; print $1, $2, "→", $0} END{print "총", count+0, "건"}' train.log

# M13. [목적] ERROR와 그 직후 자동복구(INFO) 로그를 짝지어 "복구 성공률"을 계산한다
# [설명] awk는 한 줄씩 순차 처리하므로, 상태 변수(플래그)를 두면 "이전 줄이 ERROR였는가"를
#        기억했다가 다음 줄에서 판단할 수 있습니다. 로그 상태 머신의 가장 기본적인 형태입니다.
awk '
  /ERROR/{err++; flag=1; next}
  flag==1 && /Reducing|Retrying|retry/{recovered++; flag=0}
  {flag=0}
  END{printf "ERROR %d건 중 자동복구 %d건 (%.0f%%)\n", err, recovered, recovered/err*100}
' train.log

# M14. [목적] 클래스별 라벨 개수와 전체 대비 비율(%)을 함께 보여주는 리포트를 만든다
# [설명] awk 하나로 두 번 반복(집계 → 비율 계산)해야 하는 경우, 배열에 저장해 두었다가
#        END 블록에서 전체 합계를 이용해 재계산하는 패턴이 실무 표준입니다.
cd ~/kdt-linux/dataset/kimchi/work
awk '{cnt[$1]++; total++}
     END{for(c in cnt) printf "class %s: %4d건 (%5.1f%%)\n", c, cnt[c], cnt[c]/total*100}' *.txt | sort

# M15. [목적] 여러 조별로 나뉜 데이터셋(팀별 폴더)의 이미지 수를 한 번에 집계해 진행 상황 보고서를 만든다
# [설명] FILENAME에 경로 구분자(/)가 포함되어 있을 때 split()으로 "상위 폴더명"만 뽑아
#        그룹(팀·조)별로 묶어 집계하는 실무 패턴입니다.
find ~/kdt-linux/dataset -name "*.txt" ! -path "*/work/.sedbak/*" 2>/dev/null | \
  awk -F'/' '{team=$(NF-1); cnt[team]++} END{for(t in cnt) print t, cnt[t]}'





연결점: M11처럼 "목표 지표를 처음 만족한 지점 찾기"는 안내서 교과 14·15의 목표 성능(mAP@0.5 0.7, AP 0.7, Top-1 80%) 달성 여부를 최종 발표 자료에 정량적으로 제시할 때 그대로 쓰는 방식입니다.
