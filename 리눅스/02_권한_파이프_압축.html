02

권한이란, 파일에 채우는 열쇠입니다

rwx 3×3 구조 — "나 / 같은 팀 / 나머지 전부"

집 현관문을 생각해보세요. 내 방 문은 나만 열 수 있고, 거실 문은 가족 모두 열 수 있죠. 리눅스의 모든 파일도 똑같이, 누가 읽고(Read)·고치고(Write)·실행(eXecute)할 수 있는지가 정해져 있습니다.

터미널
권한 눈으로 보기
$ ls -l make_sample_dataset.sh
-rwxr-xr--  1  kdt  ai-team  4096  Aug 26  make_sample_dataset.sh
3명(나/그룹/나머지) × 3권한(읽기/쓰기/실행) = 총 9자리
기호파일에서디렉토리(폴더)에서 ★
r (읽기)내용 보기목록 조회 (ls)
w (쓰기)내용 수정안에 파일 생성/삭제
x (실행)프로그램처럼 실행안으로 들어가기(cd) 가능 여부
⭐ 함정 조심 디렉토리에 r만 있고 x가 없으면 ls는 되는데 안으로 못 들어갑니다(cd 실패). 반대로 x만 있으면 목록은 못 보지만, 정확한 파일명을 알면 그 안의 파일에는 접근할 수 있습니다. 이 둘의 차이는 실습 2-1에서 직접 몸으로 체험합니다.
💬 왜 배우나요?

㈜비솔에서 제공하는 실제 데이터는 회사 데이터 보안 규정에 따라 다뤄야 합니다. 실수로 누구나 고칠 수 있게 열어두면 안 되는 자료도 있습니다. "이 파일을 누가 만질 수 있는지"를 내 손으로 정하는 법을 오늘 배웁니다.

03

숫자로 권한 쓰기 — 8진수 표기

rwx를 매번 글자로 안 쓰고, 숫자 세 자리로 줄여 씁니다.

규칙은 간단합니다. r=4, w=2, x=1 이고, 있으면 더하고 없으면 0입니다.

자주 쓰는 값의미용도
755rwxr-xr-x실행 스크립트, 디렉토리
644rw-r--r--일반 파일, 설정 파일
700rwx------개인 전용 폴더
600rw-------SSH 개인키, API 키 파일 (필수)
444r--r--r--데이터셋 원본 보호
775rwxrwxr-x팀 공유 디렉토리
터미널
숫자로 지정 연습
$ touch practice.sh
$ chmod 755 practice.sh; ls -l practice.sh
-rwxr-xr-x
$ chmod 644 practice.sh; ls -l practice.sh
-rw-r--r--
$ chmod 700 practice.sh; ls -l practice.sh
-rwx------
04

권한 바꾸는 명령어 모음

chmod, chown, chgrp, umask — 각각 무슨 일을 하는지
chmod 755 run.sh
숫자(8진수) 방식으로 권한을 한 번에 지정
chmod u+x run.sh
기호 방식: 소유자(u)에게 실행(x) 권한 추가
chmod go-w data/
그룹(g)과 나머지(o)에게서 쓰기(w) 권한 제거
chmod -R 444 raw/
-R = 하위 폴더·파일까지 전부 재귀 적용
chown kdt:ai-team file
파일의 소유자:그룹을 바꾸기 (sudo 필요)
chgrp ai-team file
그룹만 바꾸기
umask
새 파일을 만들 때 기본으로 적용되는 권한 마스크 확인 (보통 0022)
터미널
기호 방식 vs 숫자 방식 비교
$ touch demo.txt
$ chmod u+x demo.txt; ls -l demo.txt   # 나에게 실행 권한 추가
-rwxr--r--
$ chmod u-x demo.txt; ls -l demo.txt   # 다시 제거
-rw-r--r--
$ chmod go-w demo.txt; ls -l demo.txt  # 원래도 없었지만 확실히 그룹·기타 쓰기 제거
-rw-r--r--
글자뜻
u나 (user, 소유자)
g그룹 (group)
o나머지 (others)
a전부 (all)
+ / -권한 추가 / 제거

바로가기(링크) — 하드링크 vs 심볼릭 링크

윈도우 바탕화면의 "바로가기 아이콘"과 비슷하지만, 사실 두 종류가 있습니다.
터미널
명령 형태
ln  원본 하드링크명        # 하드링크: 같은 실제 데이터를 가리킴
ln -s 원본 심볼릭링크명    # 심볼릭링크: 경로를 가리키는 바로가기 ★ (오늘은 이걸 주로 씁니다)
심볼릭 링크는 진짜 파일이 아니라, 진짜 파일을 "가리키는 이정표"
하드링크심볼릭 링크
원본 삭제 시데이터 그대로 유지됨깨짐 (broken link)
폴더도 가능?불가능가능
다른 디스크로도 가능?불가능가능
실무 사용 빈도낮음높음
터미널
직접 차이 확인해보기
$ cd /tmp && mkdir linktest && cd linktest
$ echo "원본 데이터" > original.txt
$ ln original.txt hard.txt        # 하드링크
$ ln -s original.txt soft.txt     # 심볼릭 링크
$ ls -li                          # -i : 고유번호(inode) 표시
original.txt 와 hard.txt 는 번호가 같음 (같은 실체)
soft.txt 는 다른 번호, l 로 시작

$ rm original.txt                 # 원본 삭제!
$ cat hard.txt                    # → 정상 (데이터 유지됨)
원본 데이터
$ cat soft.txt                    # → 에러! (깨진 링크)
cat: soft.txt: No such file or directory
💬 심볼릭 링크가 실제로 필요한 상황

문제: 조각김치 데이터 1,000장(원본 수십 GB)을 train/val/test로 나눠야 합니다. 복사하면 용량이 두 배가 됩니다. 학생 PC의 SSD는 512GB뿐입니다.
해결: 원본은 한 곳에 그대로 두고, 분할 폴더에는 링크만 만듭니다.

터미널
데이터셋에 실제 적용
$ cd ~/kdt-linux/dataset/kimchi
$ ln -s ../../raw/kimchi_0001.jpg images/train/kimchi_0001.jpg
$ ls -l images/train/
lrwxrwxrwx  1 kdt kdt  30  kimchi_0001.jpg -> ../../raw/kimchi_0001.jpg
맨 앞 글자가 l이면 링크라는 표시이고, -> 뒤에 원본 위치가 보입니다. 5일차 split_dataset.sh에서 이 기법을 옵션으로 자동화합니다.

디스크 용량 확인하기

df와 du, 이름은 비슷한데 완전히 다른 일을 합니다.
df -h
디스크 전체(파일시스템)의 여유 공간을 보여줍니다.
du -sh 폴더
특정 폴더 하나가 총 몇 GB인지 보여줍니다.
du -h --max-depth=1 폴더 | sort -rh
하위 폴더별 용량을 큰 순서로 정렬해서 보여줍니다. ★ 가장 자주 씀
터미널
용량 확인 연습
$ df -h                                       # 파일시스템별 여유 공간
$ du -sh ~/kdt-linux                          # 특정 폴더 총 용량
42M   /home/kdt/kdt-linux
$ du -h --max-depth=1 ~/kdt-linux | sort -rh   # 하위 폴더별 큰 순 ★
42M   /home/kdt/kdt-linux
38M   /home/kdt/kdt-linux/dataset
3M    /home/kdt/kdt-linux/backup
💬 실전 팁

교과 5·8에서 학습 체크포인트(.pt) 파일이 쌓여 디스크가 꽉 차는 사고가 자주 납니다. du -h --max-depth=1 ~ | sort -rh 는 그때 가장 먼저 치는 명령입니다.

08

모든 명령어는 3개의 문을 갖고 있어요

표준 입력·표준 출력·표준 에러 — 아주 쉬운 비유로 이해하기
모든 명령어는 "받는 문" 하나, "내보내는 문" 두 개(정상/에러)를 가진다
  • stdin (0) — 명령어가 받아들이는 입력 통로
  • stdout (1) — 정상적인 결과가 나가는 통로 (평소 화면에 보이는 것)
  • stderr (2) — 에러 메시지가 나가는, 별도의 통로
💬 왜 두 개로 나눠져 있나요?

정상 결과와 에러 메시지가 같은 통로로 나오면 구분하기 힘듭니다. 리눅스는 처음부터 이 둘을 분리해뒀기 때문에, "에러만 숨기고 정상 결과만 저장"하는 것 같은 정교한 제어가 가능합니다. 다음 섹션에서 바로 해봅니다.

09

리다이렉션 — 결과를 화면 대신 파일로

>, >>, 2> 세 가지 화살표의 차이
명령 > 파일
정상 결과를 파일에 저장 (기존 내용은 지워짐, 덮어쓰기)
명령 >> 파일
정상 결과를 파일 맨 뒤에 이어붙이기 (기존 내용 유지)
명령 2> 파일
에러 메시지만 파일로 보내기
명령 &> 파일
정상 결과 + 에러 메시지 둘 다 파일로
명령 2>/dev/null
에러 메시지를 그냥 버리기 (화면에도 파일에도 안 남김) ★
명령 < 파일
파일 내용을 입력으로 사용하기
터미널
덮어쓰기(>) vs 이어붙이기(>>) 차이 확인
$ echo 첫줄 > note.txt
$ cat note.txt
첫줄
$ echo 두번째줄 > note.txt    # > 는 덮어쓰기! 첫줄이 사라짐
$ cat note.txt
두번째줄
$ echo 세번째줄 >> note.txt   # >> 는 이어붙이기, 기존 내용 유지
$ cat note.txt
두번째줄
세번째줄
터미널
에러만 숨기기
$ find / -name "*.pt" 2>/dev/null   # 권한 오류 메시지는 숨기고 결과만 화면에
⭐ 실무 예시 python train.py > train.log 2>&1 & — 학습 로그 전체(정상+에러)를 파일 하나로 모으고 백그라운드로 실행합니다. 2>&1은 "stderr(2)를 stdout(1)이 가는 곳으로 합쳐라"는 뜻입니다. 교과 5·8·14의 장시간 학습에서 로그 남길 때 반드시 씁니다.
10

파이프(|) — 명령어를 레고처럼 연결하기

"하나의 프로그램은 한 가지 일만 잘 하게 하고, 서로 연결해서 쓴다" — 유닉스 철학

공장의 컨베이어 벨트를 떠올려보세요. 한 기계에서 나온 결과물이 다음 기계로 그대로 흘러 들어갑니다. 파이프(|)는 한 명령어의 출력(stdout)을, 다음 명령어의 입력(stdin)으로 그대로 넘겨주는 연결관입니다.

"목록 뽑기" → "jpg만 걸러내기" → "개수 세기" — 세 기계를 파이프로 이어붙인 것
터미널
기본 파이프 실습
$ ls *.txt | wc -l                # 텍스트 파일 개수
999
$ ls | grep jpg                   # jpg 들어간 줄만 걸러내기
$ ls | grep jpg | wc -l           # 걸러낸 것의 개수까지 세기
999

파이프를 조립하는 부품 명령어들

명령역할자주 쓰는 옵션
cat파일 내용 출력-n 줄번호
head / tail앞/뒤 N줄만 보기-n 20, tail -f 실시간
wc개수 세기-l 줄, -w 단어, -c 바이트
sort정렬-n 숫자, -r 역순, -k2 2번째 필드
uniq중복 처리-c 개수 세기, -d 중복만
cut글자 중 특정 열만 잘라내기-d' ' 구분자, -f1 몇 번째
tr문자 바꾸기tr ' ' '_' 공백을 밑줄로
xargs입력을 다음 명령의 인자로 바꿔줌-n1, -I{}
tee화면에 보여주면서 동시에 파일 저장-a 이어붙이기

하나씩 감을 잡아봅시다. 각 부품이 뭘 하는지 눈으로 확인하는 게 목표입니다.

터미널
부품별 미니 예제
$ echo -e '3\n1\n2\n1' | sort              # 숫자를 줄마다 늘어놓고 정렬
1
1
2
3
$ echo -e '3\n1\n2\n1' | sort | uniq -c     # 정렬 후 중복 개수 세기
2 1
1 2
1 3
$ echo 'a b c' | cut -d' ' -f2              # 공백 기준 2번째 글자만
b
$ echo 'hello world' | tr ' ' '_'           # 공백을 밑줄로 치환
hello_world
$ ls *.jpg | head -3 | tee /tmp/first3.txt # 화면에 보여주면서 파일에도 저장
uniq -c는 반드시 정렬된 상태여야 제대로 셉니다. sort를 빠뜨리면 결과가 이상해집니다 — 이건 실습에서 자주 나오는 실수이니 꼭 기억해두세요.
💬 왜 이렇게 쪼개서 쓰나요?

"jpg 파일 개수를 세는 프로그램"을 새로 만들 필요가 없습니다. 이미 있는 작은 도구를 레고처럼 이어붙이면 됩니다. 이 습관이 익숙해지면, 사진 몇 천 장 중 "이물 라벨이 몇 개인지" 같은 것도 명령어 한 줄로 셀 수 있게 됩니다.

실습 · 심볼릭 링크로 데이터셋 분할 ★

Step 1. 링크 기본 동작 재확인

앞서 06번 섹션에서 해본 실험을 다시 짧게 반복하며 몸에 익힙니다. 이미 했다면 넘어가도 됩니다.

Step 2. 실무 적용 — 링크 방식 분할

터미널
이미지 목록 무작위로 나누기
$ ls raw/*.jpg | shuf --random-source=<(yes) > /tmp/all_imgs.txt
$ wc -l /tmp/all_imgs.txt
$ head -700 /tmp/all_imgs.txt              > /tmp/train.txt
$ sed -n '701,850p' /tmp/all_imgs.txt      > /tmp/val.txt
$ sed -n '851,$p'   /tmp/all_imgs.txt      > /tmp/test.txt
$ wc -l /tmp/train.txt /tmp/val.txt /tmp/test.txt
700 /tmp/train.txt
150 /tmp/val.txt
150 /tmp/test.txt
head -700은 앞 700줄, sed -n '701,850p'는 701번째부터 850번째 줄까지만 뽑는 명령입니다. 이렇게 목록을 700:150:150(=7:1.5:1.5)으로 나눕니다.
터미널
링크 생성 함수 만들어 실행
link_split () {
    SPLIT=$1          # train / val / test
    LIST=$2
    while read -r img; do
        base=$(basename "$img" .jpg)
        ln -sf "$(realpath "$img")"                images/$SPLIT/$base.jpg
        [ -f "raw/$base.txt" ] && \
          ln -sf "$(realpath raw/$base.txt")"       labels/$SPLIT/$base.txt
    done < "$LIST"
}

link_split train /tmp/train.txt
link_split val   /tmp/val.txt
link_split test  /tmp/test.txt
처음 보는 형태라 낯설 수 있습니다. 지금은 "폴더 안 이미지 목록을 하나씩 읽으면서, 각각 링크를 만들어주는 반복 작업"이라는 정도만 이해해도 충분합니다. 함수와 반복문은 4일차에 자세히 배웁니다.
